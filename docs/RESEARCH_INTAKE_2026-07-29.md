# Приём доноров 2026-07-29 — разбор списка владельца + усиление

Правило чтения: **лицензию проверять по файлу LICENSE перед взятием кода, не по этой таблице и
не по памяти.** Здесь — гипотеза лицензии и стек-фильтр. `Python` в стек-фильтре значит «код не
берём никогда, только принцип»: LifeOS — vanilla JS в браузере, сервера нет.

## Часть 1. Список владельца — честный разбор

| Донор | Что это | Стек | Вердикт |
|---|---|---|---|
| **Graphiti** (getzep) | темпоральный граф для агентов | Python + Neo4j | **Уже внутри.** Главный донор с 2026-07-22. Реализовано: bi-temporal `since`/`until` у рёбер, инвалидация факта вместо удаления, dedup по энтропии имени + 3-граммным шинглам + Жаккару (закон №4), entity-resolution людей. | **PyTorch Geometric** | графовые нейросети, link prediction | Python + CUDA | **Нет.** Требует обучения на большом графе; у тебя сотни узлов, а не миллионы. Link prediction без обучения даёт **Adamic-Adar / common-neighbors** — тридцать строк на JS, уже в очереди (I12). |
| **KnowledgeGraphQA-Langgraph** | LangChain + LangGraph + Neo4j | Python | **Нет.** Обвязка над чужими сервисами. |
| **awesome-graph-universe** | каталог | — | **Как индекс — да.** Читать при поиске конкретного алгоритма, донором не считать. |

**Почему «нет» — не осторожность, а твоя же формулировка.** Ты сказал: «граф как интерфейс
бесполезен» и «инсайт — это не связь, инсайт — это вывод». Все четыре проекта производят СВЯЗИ.
Кратный рост даёт не количество рёбер, а переход от рёбер к выводам — и то, что ниже, выбрано
по этому признаку.

## Часть 3. Порядок, если брать

Считано по одному признаку: **на сколько выводов о твоём мышлении это влияет.**

1. **az.js** — точность тем. Уже работающие выводы становятся правдивее. Один день.
2. **graphology** — четыре пункта очереди (I7–I10) закрываются разом, чистым JS. Два-три дня.
3. **«On this day»** — время появляется без единой новой зависимости. Полдня.
4. **transformers.js эмбеддинги** — «связано по смыслу», движок уже утверждён.
5. **Yjs** — телефон и ноутбук перестают быть двумя разными LifeOS. Самое дорогое, самое нужное.

Пункты 1, 2, 5 — новые зависимости. **Решение твоё, не моё** (CLAUDE.md §2).

## Часть 4. Чего в списке НЕТ и почему

Ни одной библиотеки, которая рисует граф красивее. Ни одного GraphRAG-стека. Ни одной LLM-обвязки.
Причина одна и она твоя: **продукт должен показывать результат работы движка, а не его устройство.**
Всё, что выше, добавляет ВЫВОДЫ или УБИРАЕТ трение — и ничего не добавляет в витрину внутренностей.
