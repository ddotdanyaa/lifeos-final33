# MVP_EVOLUTION_LOOP — как продукт улучшает сам себя

Документ 5 из 5 к `docs/MVP_HARD_SPEC.md`. Отвечает на главное замечание внешней ревизии:
спека описывает, как система учится **на данных владельца**, но не описывает, как она предлагает
изменения **в себе самой**.

**Измерено:** `grep selfImprove|proposeImprovement|improvement|weakestPoint` по `app.js` —
**ноль совпадений**. Этот контур не существует. Ревизия права полностью.

---

## 1. Два разных цикла, которые постоянно путают

| | Цикл обучения (есть) | Цикл эволюции (нет) |
|---|---|---|
| Что меняет | ранжирование предложений | **поведение продукта** |
| Из чего | журнал решений владельца | ошибки самого журнала + вечерние строки теста |
| Как часто | при каждом решении | раз в неделю |
| Кто утверждает | никто, это память | **владелец, явно** |
| Где живёт | `state.decisions` | `state.improvements` — **завести** |
| Результат | «берёшь 6 из 8» | «предлагаю перестать показывать тип X» |

Первый цикл делает предложения точнее. Второй отвечает на вопрос владельца, который до сих пор
не закрыт ничем: **«что сама система считает своим самым слабым местом сейчас».**

## 2. Контур эволюции

```
дневные данные                     что уже есть
   ├ журнал решений                state.decisions          ✓
   ├ ставки и их исход             state.bets               ✓
   ├ дрейф и канарейка             computeCalibration       ✓
   ├ лесть против пользы           computeSycophancy        ✓
   ├ мёртвые контролы              tools/audit-liveness     ✓
   └ вечерняя строка владельца     IMPROVEMENT_LEDGER       ✓
        ↓
   недельная сводка ошибок         weeklySelfReview()       ✗ писать
        ↓
   кандидат-улучшение              state.improvements       ✗ писать
        ↓
   ПОКАЗ ВЛАДЕЛЬЦУ с основанием    экран «Что я о себе понял» ✗ писать
        ↓
   владелец: принять / отклонить / отложить
        ↓
   изменение поведения             только принятое           ✗
        ↓
   повторное измерение через неделю: стало лучше или нет
```

Пять из одиннадцати звеньев уже стоят. Отсутствует середина — та, что превращает накопленные
факты в **предложение о самом продукте**.

## 3. Что система имеет право предлагать про себя

Строго ограниченный список. Всё, чего в нём нет, — не предлагается вовсе.

| Кандидат | Основание в данных | Что меняется |
|---|---|---|
| «Перестать показывать тип X» | доля принятий ≤ 0,1 при ≥ 20 решениях | тип уезжает в «ещё», не удаляется |
| «Поднять порог похожести» | вердиктов «новое» больше, чем «дубль», при высоком сходстве | число в `similar-thoughts` |
| «Понизить порог похожести» | владелец сам объединяет то, что система развела | то же |
| «Тип инсайта Y бесполезен» | ни один за 3 недели не привёл к действию | ранг типа |
| «Экран Z не открывался ни разу» | `state.surfaceUsage` | предложить убрать из главного меню |
| «Контрол мёртв» | `tools/audit-liveness` | починить или снять |
| «Разбор ошибается по вечерам» | `dayPart` в журнале, `buildOwnerProfile` уже это считает | осторожнее вечером |
| «Догадки о датах не сбываются» | сравнение догадки с правкой владельца | смена стратегии догадки |

**Чего система предлагать не имеет права никогда:** удалять данные, менять инварианты
безопасности (CLAUDE.md §7), отключать проверки, понижать планку мёртвых контролов, менять
собственные пороги без владельца, добавлять зависимости.

## 4. Форма предложения — та же, что для мыслей владельца

Симметрия здесь не эстетика: владелец уже умеет читать построчный разбор с цитатой и вердиктом.
Предложение о продукте показывается **тем же компонентом**, что и вывод из мысли.

```
Что я о себе понял за неделю

├ Я показываю «напоминание» зря
│ Ты отклонил 19 из 21 за две недели
│ по твоим решениям · измерено      [Убрать в «ещё»] [Оставить] [Позже]
│
├ Я слишком легко считаю мысли новыми
│ Ты 6 раз сам объединил то, что я развёл
│ мало данных: 6 из 8 · предположение   [Понизить порог] [Оставить] [Позже]
│
└ Мой самый слабый участок сейчас
  Догадки о датах: 4 из 11 ты поправил
```

**Последняя строка обязательна.** Ровно на неё нет ответа сегодня, и она — прямой ответ на
вопрос из внешней ревизии «что система считает своим самым слабым местом».

---

## 5. Защита от деградации

Внешняя ревизия справедливо боится: владелец случайно подтвердит ерунду, и система поедет.
Четыре защиты, три из них уже в коде:

| Защита | Есть? | Где |
|---|---|---|
| Канарейка: 50 вердиктов вне обучения, падение точности → стоп | движок **есть**, автозаморозки **нет** | `app.js:8382–8421` |
| Детектор дрейфа: история обнуляется, статус «учусь заново» | **есть** | `app.js:8325` |
| Антилесть: согласие отделено от пользы | **есть** | `app.js:8479` |
| **История эволюции: отменить последние N изменений поведения** | **нет** | снимков всего 6 (`app.js:2556`) |

Каждое принятое улучшение записывается отдельной строкой с датой и основанием, и отменяется
поодиночке. Без этого «система стала лучше» — утверждение, которое нечем проверить и нечем
откатить.

## 6. Ритм

| Когда | Что |
|---|---|
| Каждый вечер | одна строка в ledger, 2 минуты (документ 4 §4) |
| Раз в неделю, воскресенье | сводка + 1–3 кандидата, не больше |
| Раз в месяц | перепроверка канарейки |
| При дрейфе | немедленно, вне расписания |

**Не больше трёх кандидатов за раз.** Десять предложений об изменении продукта владелец не
прочитает, а согласится со всеми — и это будет ровно та деградация, от которой защищается §5.

## 7. Очередь работ по этому документу

Порядок — от дешёвого к дорогому, каждый пункт самостоятельно полезен.

1. **`freezeCanary` в загрузку** — один вызов, защита из инертной становится рабочей.
2. **Экран «Что я о себе понял»** — читает то, что уже считается (`computeCalibration`,
   `computeSycophancy`, `surfaceUsage`, liveness), ничего не изобретая.
3. **`state.improvements`** — коллекция кандидатов с основанием, вердиктом и датой.
4. **Недельная сводка** — собирает кандидатов из §3 по правилам, не по вдохновению.
5. **История эволюции с поштучной отменой** — и поднятие лимита снимков с 6 осознанно.

Пункты 1–2 входят в Срез Д. Пункты 3–5 — первая неделя после старта тестирования, на данных,
которых сегодня ещё нет: предлагать улучшения не из чего, пока журнал не наполнился.
