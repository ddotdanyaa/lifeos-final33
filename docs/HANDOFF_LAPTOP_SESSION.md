### 2.1 Голос — вход №1 в сценарии владельца
Сценарий начинается с 20–30 голосовых за день. Расшифровки нет: whisper.cpp / vosk в облаке не
запускаются, микрофона нет. На ноутбуке — есть.
- Прогнать спеки, которые в облаке падали ПО СРЕДЕ: голос, микрофон, ALAC через ffmpeg.
- Довести цепочку: голосовое → расшифровка → разбор на артефакты → предложения → чеки.
- Провайдер обязан быть честным: `not-connected` / `permission-required`, никогда не имитировать.

### 2.2 Локальная модель (Ollama) — Этап B разбора захвата
`RR-001 Этап A` (лексический разбор) сделан; Этап B — LLM-проход по неразобранному — в облаке
не проверить. На ноутбуке: поднять Ollama, прогнать разбор на настоящем вечернем дампе из
20–30 записей, сравнить с лексическим по числу артефактов и по числу ошибок.
**Граница:** LLM предлагает, но ничего не пишет сам — только proposal → подтверждение → чек (§7).

### 2.3 Настоящие эмбеддинги (I5)
`@huggingface/transformers` — модель надо скачать, в облаке не проверяется. Сейчас работает
лексическая половина («Похожее по тексту») и честный статус «поиск по смыслу недоступен».
На ноутбуке — включить и **замерить**, а не поверить: сравнить пары, которые находит лексика,
с теми, что находит смысл, и выбрать порог ПО ЗАМЕРУ (так уже делалось для `SIMILAR_MIN_SCORE`).

### 2.4 Распознавание чеков с фото
`tesseract.js` есть в списке движков, OCR не сделан. Поэтому «Хранителя чеков» из канона в
списке агентов НЕТ — и это правильно: заглушек не держим. На ноутбуке можно сделать по-честному.

### 2.5 Живое взаимодействие
Скриншоты облако снимать умеет (и это уже ловило дефекты, которых не видели зелёные тесты).
Чего облако не умеет: настоящие клики, ввод, скролл, тач, мобильный экран, drag-n-drop.
Прогнать руками сценарий вечернего дампа целиком и записать найденное спеками.

### 2.6 Полный прогон набора
116 спек одним воркером в облаке — очень долго, последний полный прогон был много пакетов назад.
На ноутбуке прогнать всё, разделив своё от чужого: **база для сравнения — прогон базового
коммита, а не память** (на `0ba483a` падало 15 спек, все по среде).

## 4. Ловушки, купленные болью (полный список — `MEMORY.md` §3–§4)

Самое дорогое из последнего прогона:

- **Подстрочное сравнение по-русски ВРЁТ** — уже пять случаев. Сопоставление темы идёт по
  основам (`lifeTermStem`), одинаковым на всех экранах. Минисёрч морфологии не знает: prefix +
  fuzzy 0.2 не покрывают падеж, поэтому «машиной» не находило «машину».
- **Узел графа жизни несёт id самой сильной проекции**, а не того объекта, от которого ищешь.
  Дважды это делало функцию мёртвой без единой ошибки. Искать через `lifeGroupKeyFor`.
- **`node --check` не ловит ReferenceError.** Удалённая переменная с оставшейся ссылкой проходит
  и синтаксис, и smoke — и валит экран в рантайме. Ловит только живой прогон.
- **`normalizeState` — белый список.** Новое поле состояния добавлять И в дефолты, И в
  `normalizeState`. Поле НА АРТЕФАКТЕ переживает нормализацию, поле состояния — нет.
- **Читать лог Playwright только со снятыми ANSI** (`sed 's/\x1b\[[0-9;]*[A-Za-z]//g'`), иначе
  падения невидимы для grep — так однажды 19 падений были приняты за ноль.
- **Правило сворачивания панели:** сворачивается только то, у чего есть СОБСТВЕННОЕ рабочее
  место; в заголовке всегда счётчик и честный статус. Первая попытка свернула связи и статус
  провайдера — две спеки упали по делу, и правильно: это усугубляло ту самую жалобу владельца.

## 5. Гейты перед «готово»

```
npm start                                        # один сервер, порт 4173, лишние гасить
npm run verify                                   # node --check + smoke (86 маркеров)
for f in tools/audit-*.mjs; do node "$f"; done   # 6 падений выше — ожидаемы
node tools/build-public.mjs                      # после любых правок ui/**, app.js, styles.css
npx playwright test output/playwright/<spec>.mjs --workers=1 --reporter=line
```

Плюс правило владельца: **каждый пакет — живой прогон в браузере (probe), а не «на глаз»**.
Пробы этого прогона нашли три дефекта, которых не увидела ни одна зелёная спека, и два из них
были старше самих фич.
