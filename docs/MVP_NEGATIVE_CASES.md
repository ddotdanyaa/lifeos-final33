## 0. Находка, ради которой стоит читать дальше

**Защиты от двух вкладок в проекте нет вообще.**

`grep BroadcastChannel|navigator.locks|storage event|writeLock` по `app.js` — **ноль совпадений**.
Хранилище — IndexedDB со снимком всего состояния. Значит: две открытые вкладки LifeOS = последняя
запись затирает состояние целиком, включая мысли, надиктованные в другой вкладке.

Это не теоретический риск. Владелец начинает ежедневное использование 1 августа, работает с
ноутбука и телефона, и оставленная открытой вкладка — норма, а не ошибка. **Один забытый таб
может стереть день записей, и никто этого не заметит**, потому что запись прошла «успешно».

Приоритет: выше всех срезов Б–Д. Стоимость минимального лечения — часы, не дни (см. О-1 ниже).

## 1. Отказы системы

| Код | Ситуация | Что видит владелец | Что сохраняется | Как выйти |
|---|---|---|---|---|
| О-1 | **Две вкладки пишут одновременно** | *(сегодня — ничего, тихая потеря)* → должно: «LifeOS открыт ещё в одной вкладке. Работаю только здесь» | всё | закрыть лишнюю; вторая вкладка уходит в режим чтения |
| О-2 | Диктовка оборвалась на середине | «запись прервана, сохранено N секунд» | аудио до обрыва | «дописать голосом» |
| О-3 | Расшифровка не получилась | «текст не распознан, аудио на месте» | файл + запись | вписать руками |
| О-4 | Модель вернула мусор (текст без структуры) | разбор молчит, показан сырой текст | всё | «сохранить как есть» |
| О-5 | Две модели не согласны | показывается **обе** версии с источником каждой | обе | владелец выбирает |
| О-6 | Провайдер недоступен | `not-connected` / `provider_unavailable` дословно | всё | одна кнопка «подключить» |
| О-7 | Интернет пропал | ничего не меняется — продукт локальный | всё | — |
| О-8 | Разбор > 15 с | уходит в фон, поле освобождается | черновик | уведомление по готовности |
| О-9 | Хранилище переполнено | «браузер больше не даёт места, освобождено N» | всё до предела | экспорт + очистка корзины |
| О-10 | Состояние повреждено | `corruptRecords` в Контроле | остальное | откат из снимка |
| О-11 | Откатов не хватило | **снимков всего 6** (`app.js:2556`) — внешний текст просил «отменить 20» | последние 6 | поднять лимит осознанно |
| О-12 | Файл больше памяти вкладки | сказать прямо, а не обрезать молча (Т3) | ничего | — |

## 2. Ошибки владельца

| Код | Ситуация | Поведение |
|---|---|---|
| В-1 | Сказал половину мысли | сохраняется как есть; разбор молчит, а не додумывает |
| В-2 | Передумал в момент разбора | «Отменить» возвращает черновик целиком, включая файлы |
| В-3 | Случайно отправил | принятое сворачивается в строку и отменяемо, пока запись на экране |
| В-4 | Загрузил 50 файлов | очередь с видимым счётчиком, разбор по одному, ввод не блокируется |
| В-5 | Загрузил один и тот же файл дважды | вторая копия не заводится — совпадение по имени и размеру |
| В-6 | Написал 3 символа | не шум по умолчанию: сохраняется, разбор честно молчит |
| В-7 | Написал 40 000 символов | разбирается кусками, показывается прогресс по кускам |
| В-8 | Написал матом | ничего не фильтруется. Это его записи |
| В-9 | Уснул с открытым микрофоном | тишина > 2 мин → запись закрывается сама, сохраняется что было |
| В-10 | Диктовал в машине (шум) | низкое качество расшифровки помечается, не выдаётся за точный текст |
| В-11 | Дважды вынес противоположный вердикт | последний побеждает, оба лежат в журнале — дрейф это увидит |
| В-12 | Удалил нужное | корзина 30 дней (`TRASH_GRACE_DAYS`) |

## 3. Границы данных

| Код | Ситуация | Правило |
|---|---|---|
| Г-1 | Мысль относится к двум проектам | связывается с обоими. Выбор одного — потеря |
| Г-2 | Мысль упоминает пять людей | все пятеро связываются; предложений о связи — не больше трёх на экран |
| Г-3 | Похожесть в зоне 0,4–0,6 | ни дубль, ни новое: система обязана сказать «не уверен» и спросить |
| Г-4 | Найдено ≥ 10 похожих | показываются 3 + «ещё N» |
| Г-5 | Дата не распознана | **догадка, помеченная догадкой** — правило владельца 2026-07-30. Никогда пустое поле |
| Г-6 | Сумма без валюты | рубли по умолчанию, пометка «валюта не названа» |
| Г-7 | Запись без единого признака | тип «мысль», не «шум». Шум — только явный дубль |
| Г-8 | Один человек под двумя именами | не сливаются автоматически; предлагается объединение с вердиктом |

## 4. Конфликты между сценариями — кто выигрывает

Внешняя ревизия права: это не расписано нигде, а конфликты возникают в первый же день.

| Конфликт | Побеждает | Почему |
|---|---|---|
| Инсайт говорит «создать проект», память говорит «такой уже есть» | **память** | предложение превращается в «дополнить существующий», с кнопкой «всё-таки новый». Плодить дубли дороже, чем спросить |
| Похожие мысли говорят «дубль», разбор нашёл новую сумму/дату | **разбор** | новые факты важнее сходства текста. Вердикт по умолчанию — «уточнение», не «дубль» |
| Профиль владельца понижает уверенность, разбор уверен | **профиль, но только до порога** | `applyOwnerProfileToProposal` `app.js:8623` понижает, но никогда не отбрасывает — решает владелец (И-1) |
| Калибровка говорит «берёшь 90 %», канарейка заморожена | **канарейка** | она смотрит не на те данные, на которых система училась. Порядок веток закреплён в `proposalsWithTrust` |
| Разбор создал и расход, и задачу об одном | **сильнейший тип** | `STRONGER_THAN_TASK_TYPES` `app.js:6133` — задача-двойник не создаётся |
| Инсайт противоречит другому инсайту | **ни один** | оба показываются рядом как противоречие (`computeContradictions` `app.js:17583`), система не выбирает за владельца |
| Вечерний итог говорит «закрыто», задача открыта | **состояние объекта** | итог пересчитывается из объектов, а не хранит своё мнение |
| Две вкладки | **та, что писала последней** *(сегодня)* → должна: **первая** | см. О-1 |

**Общий закон разрешения:** при конфликте система не выбирает молча. Она показывает обе стороны
и своё предложение, отмеченное как предложение. Молчаливый выбор — это скрытое действие, а они
запрещены (CLAUDE.md §7).
