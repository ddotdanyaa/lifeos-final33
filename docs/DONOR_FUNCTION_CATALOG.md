# DONOR FUNCTION CATALOG — полная выгрузка функций доноров (§4 шаг 6)

Это исполнение шага 6 процесса `docs/INSIGHT_ENGINE_CANON.md` §4: **«Выделить ВСЕ функции»** для каждого
донора, а не выборочно. Источник — прямой разбор живых репозиториев/документации (не память;
правило Canon «не полагаться на память»). Даты проверки и ссылки — в конце каждого блока.

## Как читать

- Каждая таблица — исчерпывающий список функций одного донора.
- `Функция` — как называет её сам донор.
- `Что делает` — механизм/алгоритм в одну строку.
- `Применимость к LifeOS` — можно ли и как адаптировать в артефактную модель (vanilla JS / IndexedDB /
  47 коллекций / proposal→receipt). Метки: **✅ прямо** (ложится на наш стек), **🔸 частично** (нужен
  честный лексический/локальный фоллбэк вместо тяжёлого рантайма), **⛔ вне стека** (сервер/облако/тяжёлый
  ML без одобрения владельца — берём только идею), **✔ уже есть** (реализовано в LifeOS).
- `Пакет` — ссылка на строку в `docs/INSIGHT_IMPLEMENTATION_QUEUE.md` (I*/M*/R*/S*/V*/G*/Q*/E*).

**Железные правила (Canon §0):** не переносим код, не копируем архитектуру, стек-фильтр жёсткий, мутации
только через proposal→preview→apply→receipt, новые тяжёлые зависимости — только по слову владельца.
