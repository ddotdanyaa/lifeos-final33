# Инженерные решения — steven-tey/precedent (репо 2/5)

Реальный клон (1.2 МБ). Перепись: **22 .tsx, 9 .ts** — маленький, но это репо про **архитектуру/shell/
навигацию/mobile**, не про объём компонентов. Прочитаны: `app/layout.tsx`, `navbar.tsx`, `modal.tsx`,
`popover.tsx`, `use-media-query.ts`, `use-scroll.ts`, `use-local-storage.ts`, `card.tsx`, `utils.ts`.
Честно: **не тяну до 100 искусственно** — здесь ~45 настоящих решений; объём наберём на dashboard-starter
и shadcn-table. Формат: ⭐ приоритет (5=обязательно…1=не для нас) + «почему» + карточки Improvement.

## ⛔ Что НЕ брать (экономит часы)
- ❌ **ClerkProvider / аутентификация** — не наш сценарий (локальная ОС, без облачного логина).
- ❌ **Next.js**: Suspense/streaming, `metadata` API, `middleware.ts`, файловый роутинг — не наш стек.
- ❌ **twMerge/clsx** (склейка Tailwind-классов) — у нас нет Tailwind.
- ❌ **Radix/vaul как React-код** — берём ПОВЕДЕНИЕ (drawer снизу, focus-trap), пишем на vanilla.
- ❌ **Vercel Analytics, ReactMarkdown** — у нас свой рендер (marked+dompurify).
- ❌ Радужный градиент-фон hero — для лендинга, не для рабочей ОС (нам нужна спокойная поверхность).

## A. Shell / Layout
1. ⭐⭐⭐⭐ **Единая типо-пара через CSS-переменные**: display-шрифт (SF Pro, локальный .otf) для заголовков + Inter для текста, подключены как `--font-display`/`--font-default`. Почему: один источник шрифтов, заголовки и текст никогда не «плывут». → у нас задать `--font-display`/`--font-ui` и не хардкодить font-family по месту.
2. ⭐⭐⭐ Фикс-подложка за всем контентом (`fixed h-screen w-full`) — дешёвая глубина без стилизации каждой секции. → у нас: спокойная `--paper` подложка, но приём тот же (один слой фона).
3. ⭐⭐⭐⭐ `main` центрирован флексом (`min-h-screen flex-col items-center`) с `max-w-screen-xl` — контент имеет читаемую макс-ширину, не растекается на весь 4K. Почему: длинные строки = плохая читаемость. → ввести `--content-max` и центрировать рабочую область.
4. ⭐⭐ Footer/Analytics вне main — служебное не в потоке контента.

## B. Навигация (navbar.tsx)
5. ⭐⭐⭐⭐⭐ **Frosted-навбар только при скролле**: `useScroll(50)` → прокрутил >50px → `border-b + bg-white/50 backdrop-blur-xl`; сверху — прозрачный. Почему: над первым экраном панель не нужна (чисто), но когда контент подъезжает под неё — нужен матовый фон для читаемости. → наша шапка сейчас всегда сплошная; сделать её матовой-на-скролле.
6. ⭐⭐⭐ Навбар `fixed top-0 z-30 transition-all` + центрированная строка `h-16 max-w-screen-xl` — стабильная высота, плавные переходы состояний.
7. ⭐⭐⭐ Кнопка-пилюля с **инвертирующим hover** (`bg-black → hover:bg-white hover:text-black`, `rounded-full`). Почему: одно главное действие в шапке визуально «капсула», hover явно меняет полярность. → наш «Ввод» в шапке привести к одному явному primary.

## C. Адаптивные оверлеи ⭐⭐⭐⭐⭐ (главное этого репо)
8. ⭐⭐⭐⭐⭐ **Один оверлей — два тела по устройству**: `useMediaQuery().isMobile` → мобайл рендерит **Drawer снизу** (с ручкой-хваталкой `h-1 w-12 rounded-full`), десктоп — **центр-Dialog** (`animate-scale-in max-w-md rounded-2xl backdrop-blur-md`). Почему drawer на мобиле: нижний лист достаётся большим пальцем одной рукой, центр-диалог — нет.
9. ⭐⭐⭐⭐ Popover тем же приёмом: мобайл → Drawer, десктоп → Popover (`animate-slide-up-fade`, `sideOffset 8`). Почему: на тач-экране крошечный поповер неудобен — лист удобнее.
10. ⭐⭐⭐ `onOpenAutoFocus preventDefault` у диалога — не выхватывает фокус рывком на первый инпут.
11. ⭐⭐⭐ Overlay c `id="modal-backdrop"` — способ узнать «есть ли открытая модалка» из любого места.
12. ⭐⭐⭐ `backdrop-blur` + полупрозрачный оверлей вместо чёрного 50% — мягче, современнее.
13. ⭐⭐⭐ Ручка-хваталка drawer (`my-3 h-1 w-12 rounded-full bg-gray-300`, sticky top) — аффорданс «тяни вниз, чтобы закрыть».

## D. Хуки (портируются в vanilla почти дословно)
14. ⭐⭐⭐⭐⭐ **useMediaQuery**: mobile ≤640 / tablet 641-1024 / desktop >1024, слушает resize, отдаёт `isMobile/isTablet/isDesktop` + размеры. → одна функция-источник брейкпоинтов вместо разбросанных `@media`/проверок ширины в JS.
15. ⭐⭐⭐⭐ **useScroll(threshold)** — булев «прокручено ниже N». → для frosted-шапки (#5).
16. ⭐⭐⭐ **useLocalStorage(key, initial)** — персист UI-состояния. → мы уже храним; приём: сохранять раскрытость панелей/тему/раскладку.
17. ⭐⭐⭐ **useIntersectionObserver** — ленивое появление/анимация при попадании в вьюпорт. → ленивый рендер тяжёлых секций (граф/списки).

## E. Карточка и типографика (card.tsx)
18. ⭐⭐⭐⭐ **Адаптивный заголовок**: мелко+жирно на мобиле (`text-xl font-bold`), крупно+тонко на десктопе (`md:text-3xl md:font-normal`). Почему: мелкому кеглю нужна жирность для читаемости, крупному — воздух и элегантность. → наш `clamp()` + смена веса по брейкпоинту.
19. ⭐⭐⭐ `[text-wrap:balance]` на заголовках/описаниях — переносы строк выровнены (нет «висячего» одного слова). → добавить `text-wrap:balance` заголовкам.
20. ⭐⭐⭐ Карточка: `rounded-xl border bg-white shadow-md overflow-hidden`, фикс-высота — единый силуэт в сетке. → свести наши карточки к одному силуэту (radius/border/shadow).
21. ⭐⭐ Gradient-clip заголовок (`bg-clip-text text-transparent`) — для акцентных заголовков; у нас — точечно, не везде.

## F. Motion (globals.css анимации)
22. ⭐⭐⭐⭐ Именованные keyframes под роли: `animate-fade-in` (оверлей), `animate-scale-in` (диалог), `animate-slide-up-fade` (поповер). Почему: каждый тип появления — своя анимация, а не одна на всё. → 3-4 именованных перехода в нашем `--ease`-словаре.
23. ⭐⭐⭐ Короткие тайминги, `ease-out`-подобные — появление быстрое, исчезновение мягкое.
24. ⭐⭐ `counting-numbers` — анимация числа при появлении (для метрик). → опционально для денежных итогов.

## G. Утилиты (портируемые)
25. ⭐⭐⭐ `nFormatter` — 1.2K / 3.4M / 1.1B компактные числа. → для крупных сумм/счётчиков.
26. ⭐⭐⭐ `timeAgo` (относительное время «5 мин назад»). → у нас есть похожее; свести к одному.
27. ⭐⭐ `truncate`/`capitalize` — мелкие, но единые. → в наш `shared.js`.
28. ⭐⭐⭐ `fetcher` с типизированной ошибкой (status + message) — единый разбор ответа. → паттерн для наших provider-вызовов (честные ошибки).

## Карточки LifeOS Improvement (топ этого репо)

### IMP-2.1 — Адаптивный оверлей Dialog↔Drawer
- **Источник:** `components/shared/modal.tsx`, `popover.tsx`
- **Идея:** один компонент модалки; `isMobile` → нижний лист с ручкой, десктоп → центр-диалог.
- **Почему лучше нашего:** у нас модалки одинаковы на всех ширинах; на телефоне центр-диалог неудобен большому пальцу, часть уезжает.
- **Как встроить:** helper `openSheet(contentHtml)` — на `isMobile()` рендерит `.sheet--bottom` с drag-handle, иначе `.dialog--center`; общий контент. Один CSS-класс-набор.
- **Эффект:** ⭐⭐⭐⭐⭐ (мобайл — половина использования)
- **Стоимость:** средняя (нужен один компонент + 2 CSS-режима + жест закрытия).

### IMP-2.2 — Frosted-шапка на скролле
- **Источник:** `navbar.tsx` + `use-scroll.ts`
- **Идея:** шапка прозрачна сверху, матовая (`backdrop-blur` + border) после прокрутки >50px.
- **Почему лучше нашего:** наша шапка всегда сплошная — тяжелит первый экран; матовость нужна только когда под неё подъезжает контент.
- **Как встроить:** scroll-listener ставит `data-scrolled` на шапку; CSS `.lifeos-public-header[data-scrolled] { backdrop-filter: blur; background: color-mix(...); border-bottom }`.
- **Эффект:** ⭐⭐⭐⭐
- **Стоимость:** низкая (10 строк JS + CSS).

### IMP-2.3 — Единый источник брейкпоинтов (useMediaQuery)
- **Источник:** `lib/hooks/use-media-query.ts`
- **Идея:** одна функция `deviceInfo()` → isMobile/isTablet/isDesktop, слушает resize.
- **Почему лучше нашего:** у нас проверки ширины разбросаны; адаптив-баги (3 экрана с overflow из D−1) — оттуда.
- **Как встроить:** `ui/lib/device.js` с `matchMedia` + подписка; отдаёт брейкпоинт в ctx; оверлеи/раскладки читают его.
- **Эффект:** ⭐⭐⭐⭐⭐ (фундамент под адаптив)
- **Стоимость:** низкая.
