# LIFEOS v1.5 — FMEA: систематический разбор отказов

**Дата:** 2026-07-28. **Метод:** сетка «компонент × класс отказа» по реальной описи репозитория,
а не свободный поток. Опись: 52 коллекции состояния, 13 движков, 9 провайдеров, 28 аудитов,
120 спеков, 31 UI-модуль, 43 инструмента, 23 пакета плана, 9 подсистем восприятия.

**Классы отказа:** отсутствие · порча данных · производительность · гонка · тихий отказ ·
ложный успех · каскад · необратимость · ресурсный предел · версионный дрейф · доверие · человек.

**Нумерация сквозная — счёт проверяем.** Фатальные (меняют план) помечены 🔴.

## I. Хранилище и состояние (1–48)

1. 🔴 `save()` сериализует ВСЁ состояние на каждое сохранение — бинарь внутри убивает автосейв.
2. base64 раздувает файл на 33% до попадания в JSON.
3. gzip по аудио даёт ~0 сжатия, но тратит CPU на каждом сохранении.
4. `CHUNK_SIZE` 120000 → десятки чанков на файл, переписываются целиком.
5. Объектное хранилище одно — отдельного места под бинарь нет.
6. `normalizeState` обходит все 52 коллекции на каждом сохранении.
7. `rebuildIndexes` вызывается 26 раз по коду, на каждый commit.
8. Автосейв 1,5 с при активной печати накладывается сам на себя.
9. Квота IndexedDB кончится молча при росте медиа.
10. `localStorage`-фоллбэк (5–10 МБ) не переживёт ни одного аудиофайла.
11. Экспорт раздувается до неоткрываемого JSON.
12. `export-roundtrip.spec` сломается при выносе бинаря, если миграция не написана.
13. Миграция старых `dataUrl` может потерять файлы при сбое посередине.
14. Blob URL не освобождается → утечка памяти в длинной сессии.
15. Две вкладки пишут одновременно → последняя затирает первую.
16. Приватное окно: всё исчезает при закрытии.
17. Очистка данных сайта браузером — без предупреждения.
18. Нет версии схемы у нового хранилища бинаря.
19. Откат схемы вниз невозможен — старый клиент не прочитает новое.
20. `schemaVersion` растёт, а миграции накапливаются без тестов на каждую.
21. Порча одного чанка ломает распаковку всего состояния.
22. Нет контрольной суммы состояния — порча заметна только по краху.
23. Нет инкрементального бэкапа — только полный.
24. Владелец не делает бэкапы, напоминания нет.
25. Восстановление из бэкапа не тестируется регулярно.
26. Коллекция `sources` растёт неограниченно — нет архивации.
27. `providerRuns` растёт на каждый вызов провайдера — вечный лог.
28. `agentRuns` и `flowRuns` растут при автономной работе быстрее всего.
29. Аудит-лог (`control`) не ротируется.
30. `chatMessages` растут без сжатия истории.
31. `transcriptSegments` на длинном аудио — тысячи записей.
32. `databaseRows` пользовательских баз неограниченны.
33. `smartHomeEvents` копятся при подключённом доме.
34. `backlinks`/`ghosts` пересчитываются, но хранятся — двойной расход.
35. Удаление помечает `deleted`, а не удаляет — состояние только растёт.
36. Нет уплотнения (compaction) удалённых записей.
37. Дедуп по checksum не покрывает почти-дубликаты.
38. `entityAliases` могут зациклиться (A→B→A).
39. `projectItems` осиротеют при удалении проекта.
40. `planBlocks` ссылаются на задачи, которых уже нет.
41. `highlights` ссылаются на позиции в тексте, который изменился.
42. `audioCheckpoints` указывают на секунды файла, который заменён.
43. `installedPacks` могут конфликтовать между собой.
44. `designProfiles` могут сломать токены темы.
45. `modelProfiles` хранят настройки моделей, которых больше нет.
46. `screenCompanionSessions` содержат снимки экрана — приватность и объём.
47. `personalTwinSnapshots` — самая чувствительная коллекция, без отдельной защиты.
48. `savedSearches` ссылаются на запросы к полям, которые переименованы.

## II. Движки — 13 зависимостей (49–90)

49. `@huggingface/transformers`: модель 40–150 МБ качается с CDN — офлайн не работает.
50. Та же: WebGPU может отсутствовать → WASM в разы медленнее.
51. Та же: обновление v4→v5 сломает API.
52. Та же: модель кэшируется в браузере и съедает квоту.
53. Та же: первый запуск выглядит зависанием без индикатора.
54. `vosk-browser`: второй STT-движок дублирует функцию Whisper — расхождение результатов.
55. Та же: словари русского языка — отдельная загрузка.
56. Та же: качество ниже Whisper, но выбор не объяснён владельцу.
57. `pdfjs-dist`: worker грузится отдельно, путь ломается при раскладке модулей.
58. Та же: защищённые паролем PDF роняют разбор.
59. Та же: сканы без текстового слоя дают пустоту, а не честный статус.
60. Та же: лимит 60 страниц молча обрезает длинные документы.
61. `tesseract.js`: OCR-языки качаются отдельно, ~10–20 МБ.
62. Та же: OCR на кириллице даёт мусор при низком качестве скана.
63. Та же: блокирует поток без worker.
64. `epubjs`: нестандартные EPUB ломают разбор спайна.
65. Та же: DRM-книги не открываются, статус может быть непонятным.
66. `fflate`: unzip больших архивов в память — пик потребления.
67. Та же: используется и для gzip состояния, и для EPUB — общий отказ роняет оба.
68. `cytoscape`: тысячи узлов кладут кадровую частоту.
69. Та же: раскладка недетерминирована — граф «прыгает» между сессиями.
70. Та же: destroy/recreate на каждый рендер (`graphEngine.destroy()`) — утечки при частых рендерах.
71. `chart.js`: перерисовка на каждый рендер без кэша.
72. Та же: конфликт с тёмной темой при смене на лету.
73. `marked`: markdown из недоверенного источника → HTML.
74. `dompurify`: единственная защита от XSS; ошибка конфигурации открывает дыру.
75. Та же: пропуск санитайза в одном месте компрометирует всё.
76. `minisearch`: индекс в памяти, растёт линейно с базой.
77. Та же: переиндексация на каждый commit — O(n) на действие.
78. Та же: русская морфология не поддерживается из коробки — «задачи» ≠ «задача».
79. `sortablejs`: drag&drop конфликтует с drop-обработчиком импорта файлов.
80. `@toast-ui/editor`: тяжёлый редактор, тянет свои стили и ломает канон дизайна.
81. Та же: конфликт CSS-переменных с `styles.css`.
82. Любая из 13: обновление ломает сборку `public-demo`.
83. Любая: уязвимость в зависимости требует срочного обновления.
84. Любая: удаление из npm (левый-пад) останавливает сборку.
85. Любая: изменение лицензии в новой версии.
86. Ни одна не проверяется на целостность (integrity hash) при загрузке.
87. Service worker кэширует старую версию движка после обновления.
88. `tools/build-public.mjs` не знает о новом движке → демо ломается.
89. Размер бандла растёт с каждым движком — холодная загрузка.
90. Новый движок вне утверждённого списка требует слова владельца — блокирует пакет.

записях; всё сверх этого — либо перечисление экземпляров вместо механизмов (каждый из 120
спеков как отдельная причина), либо переформулировки уже названного. Такой список выглядел бы
внушительнее и защищал бы хуже.
