# Бесплатные LLM-ключи: где взять, как проверить, куда вставить

Инструмент на случай, когда квота платной подписки кончилась, а работа стоять не должна.

**Что это НЕ делает:** не заводит аккаунты, не подбирает и не выпрашивает чужие ключи, не обходит
лимиты. Работает ровно на тех ключах, которые ты получил сам по ссылкам ниже. Всё остальное — либо
нарушение правил провайдера, либо чужой ключ, который отключат через день.

---

## 1. Три шага

```powershell
node tools/free-ai-keys.mjs --signup     # 1. показывает, куда нажимать за ключами
                                         # 2. вставляешь ключи в ai-keys.json (см. §2)
node tools/free-ai-keys.mjs --best       # 3. проверяет живьём и выдаёт готовую настройку
```

В терминале Windows то же самое короче: `.\tools\free-ai-keys.ps1 -Best`
(это обёртка над тем же кодом, отдельной логики в ней нет).

---

## 2. Куда класть ключи

Скопируй `tools/ai-keys.example.json` в корень проекта как `ai-keys.json` и заполни. Пустые строки
пропускаются — можно начать с одного ключа.

```json
{ "github": "github_pat_...", "groq": "gsk_...", "google": "AIza..." }
```

`ai-keys.json` закрыт в `.gitignore`. **Это не формальность:** репозиторий публичный, а ключ,
попавший в открытый git, выгребают роботы за часы. Ключи в другие файлы не клади.

### Про «посредников» — читать обязательно

**«Свой»** — запрос идёт прямо к владельцу модели. **«Посредник»** — между тобой и моделью стоит
чужой сервер, и он видит твой промпт и твой код целиком. Такие репозитории (`chatanywhere` и
подобные) действительно работают — это не обман. Но:

- отправлять туда закрытую часть LifeOS нельзя;
- они пропадают без предупреждения — держи их последними в списке, не единственными;
- разбор чужого открытого кода, черновые правки, объяснение алгоритмов — для этого они годятся.

**Ollama** — единственный вариант, где ни один байт не уходит наружу. В LifeOS он уже подключён
(`core/ollama-chat.mjs`, порт 11434).

## 4. Куда вставлять в Cursor

`Settings → Models → OpenAI API Key`. Заполнить **оба** поля:

```
Base URL : (то, что выдал --best)
API Key  : (то, что выдал --best)
```

Затем добавить имя модели в список моделей Cursor и нажать `Verify`.

**Пустое поле Base URL — причина ошибки `unauthorized user api key` почти всегда.**

### Что через свой ключ работать не будет

Проверено по докам и обсуждениям Cursor, чтобы ты не искал причину:

- **Tab-автодополнение и `Ctrl+K`** остаются на серверах Cursor и через чужой ключ не идут;
- **Composer 2.5** отвечает `This model does not support custom API keys`;
- у Cursor свой таймаут запроса, и **медленная модель отвалится** — поэтому Groq/Cerebras в списке
  первые, они самые быстрые.

Чат и обычные правки — работают.

## 5. Шлюз: вставить один раз и забыть

Проблема ручного ключа: бесплатный лимит кончается **посреди работы**, и Cursor молча перестаёт
отвечать. Шлюз держит все ключи у себя и на исчерпанном лимите переходит к следующему провайдеру
внутри того же запроса.

```powershell
node tools/ai-gateway.mjs
```

В Cursor тогда вставляется навсегда одно и то же:

```
Base URL : http://127.0.0.1:4180/v1
API Key  : lifeos            (любая непустая строка; настоящие ключи лежат в ai-keys.json)
Model    : lifeos-auto
```

Состояние — `http://127.0.0.1:4180/` (кто в обойме, кто остывает и почему).

Поведение при отказах: `429` → провайдер откладывается на время из `Retry-After`; `401` → на час
(ключ надо перевыпустить); обрыв связи → на 30 секунд. Когда не отвечает никто, шлюз возвращает
`503 provider_unavailable` — честный отказ вместо выдуманного ответа, как требует §7 CLAUDE.md.

## 6. Что означают вердикты проверки

| Вердикт | Смысл |
|---|---|
| `РАБОТАЕТ` | Пришёл непустой текст от модели. **Только это считается успехом.** |
| `ПУСТОЙ ОТВЕТ` | Код 200, но текста нет. Обычно так выглядит выбранная квота. Не успех. |
| `КЛЮЧ НЕ ПРИНЯТ` | 401/403 — ключ неверен или без нужного права (у GitHub — `Models: Read-only`) |
| `ЛИМИТ ИСЧЕРПАН` | 429, с временем повтора, если провайдер его прислал |
| `МОДЕЛЬ НЕ НАЙДЕНА` | Имя модели устарело. Проверялка сама спрашивает список у провайдера и пробует снова |
| `НЕ ОТВЕЧАЕТ` | Нет связи или не уложился в таймаут |

Если рабочих нет, `--best` **ничего не печатает** и выходит с кодом 2: вставлять в Cursor нечего,
и время на это тратить не надо.

---

## 7. Что проверено, а что нет

**Проверено прогоном** (2026-07-31, поддельные провайдеры на всех режимах отказа): различение
всех шести вердиктов; пропуск эмбеддинг-моделей при переоткрытии имени; переход шлюза через
`429 → 401 → мёртвый хост` к живому провайдеру внутри одного запроса; сквозная передача SSE-потока;
остывание с временем из `Retry-After`; честный `503`, когда живых нет.

**Не проверено вживую:** сами адреса провайдеров и их лимиты. Сетевая политика облачного контейнера
режет эти хосты, поэтому цифры в таблице взяты из публичных доков провайдеров и каталога
[amardeeplakshkar/awesome-free-llm-apis](https://github.com/amardeeplakshkar/awesome-free-llm-apis)
(MIT) на 2026-07-31. Лимиты и имена моделей дрейфуют — **живой факт даёт только запуск проверялки
на твоей машине**, для этого она и написана.
