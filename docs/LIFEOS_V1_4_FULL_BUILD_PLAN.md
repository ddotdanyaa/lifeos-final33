# LifeOS v1.4 — FULL_BUILD_PLAN (полная реализация вертикальными срезами)

Владелец (2026-07-20, вторая директива дня): «Весь скоуп — в один промпт. Но два правила
внутри оставил: порядок сборки и обязательный push после каждого блока. Работа без push в
репо не существует.» Плюс: «Перестрой план, чтобы всё на Fable переделал, и пиши дальше на
нём». Этот план ЗАМЕНЯЕТ очередь v1.3 после V0.5 (закрытые V0/V0.5 остаются в истории;
V1 CHAT_BRAIN заморожен как WIP и становится частью среза 5; V2-V5 из v1.3 растворяются в
срезы ниже — их спеки-заготовки переиспользуются, не выбрасываются).

## 0. Архитектурный закон (без изменений с v34-канона, подтверждён владельцем)

- **Single Source of Truth**: любой вход (текст, голос, фото, файл, транзакция, событие)
  становится АРТЕФАКТОМ. Все экраны — чат, дашборд, граф, финансы, таймлайн, агенты —
  только проекции слоя артефактов/сущностей/связей. Никаких модулей с собственным
  состоянием.
- **Local First**: всё возможное локально (Ollama, whisper.cpp). Cloud — только по явному
  выбору (API-ключ в настройках; BYOK-vault уже есть с P5.2).
- Стек не меняется: vanilla JS (ESM) + IndexedDB, живая оболочка `ui/*.js`, ядро `app.js`.

## 1. Правила выполнения (нарушение = стоп; слова владельца)

1. После КАЖДОГО среза: `npm run stamp` → git commit + push в текущую ветку + обновить
   `PROGRESS.md` + инструкция «как проверить за 60 секунд».
2. Срез не завершён, пока не работает в UI end-to-end. Заглушки, TODO, моки = не завершён.
3. Работа без push в репо не существует. «Готово» без коммита не принимается.
4. Блокировка → запись в BLOCKED.md, идти дальше.
5. Функции не ради количества: всё встраивается в единый слой артефактов, а не живёт
   отдельным экраном.
6. **Диета процесса** (из той же директивы): смоук — на каждый коммит; полный e2e — раз в
   день или перед пушем среза, НЕ после каждого изменения (флейки этой сессии — от
   resource contention при параллельных тяжёлых прогонах, трижды подтверждено); скриншоты —
   только при UI-изменениях; DECISIONS.md — одна запись на срез или реальную находку.
7. Хеш сборки: `npm run stamp` пишет git-hash в `index.html` (виден в шапке UI,
   `data-testid="build-version"`) и в имя SW-кэша (`service-worker.js`) — новая сборка
   гарантированно инвалидирует старый кэш. Если владелец видит «не ту» версию — первым
   делом сверить хеш в шапке с последним коммитом.
8. **Структура журналов** (по разбору владельца от 2026-07-20): `PROGRESS.md` — краткий
   индекс: карта продукта + по срезу «статус/дата/категории/зависит-от/60-сек проверка/
   долг». `DECISIONS.md` — глубокие расследования (цикл Found → Decision → Why → Verified —
   обязательный шаблон). `LESSONS.md` — переиспользуемые уроки, экономящие часы.
   `BLOCKED.md` — как раньше. Ретро-переписывание старых записей НЕ делается (низкая
   ценность против постройки продукта) — правила действуют для новых записей.
9. **Репозиторий — строительный материал** (директива владельца): перед КРУПНОЙ новой
   подсистемой — research-спринт: минимум 5-10 permissive-кандидатов (MIT/Apache/BSD),
   рейтинг по поддержке/размеру/совместимости, и Technology Decision Record в DECISIONS.md
   (зачем, какие альтернативы, почему эта, что станет причиной замены). Если готовое
   покрывает >70% задачи — интегрировать и писать только адаптер, не своё. ЖЁСТКИЙ фильтр
   нашего стека (не отменяется энтузиазмом): работает в браузере без бандлера (нативный
   ESM, UMD-сборка или отдельный локальный процесс поверх HTTP как whisper.cpp/Ollama),
   permissive-лицензия, живой проект. React/JSX/build-only библиотеки (ReactFlow, TipTap,
   remark-экосистема) в этот стек НЕ встают — их аналоги уже установлены и одобрены
   (cytoscape, @toast-ui/editor, marked, pdfjs, epubjs, minisearch, fflate, chart.js,
   sortablejs, tesseract, transformers). Приоритет всегда: уже установленный движок →
   вендорная интеграция целиком → порт алгоритма с указанием источника. Раз в несколько
   срезов — dependency audit (живость, лицензия, уязвимости, лучшие альтернативы).

## 4. Владелец-директива 2026-07-22 (финансы-автосистема + массовая интеграция + линза продаж)

Цель владельца дословно: «хочу поскорее прийти к моменту, когда начну ПОЛЬЗОВАТЬСЯ».
Приоритет №1 для этого — **финансы как автосистема**: не форма для ручного ввода, а движок,
который сам собирает доходы/расходы, считает, связывает и объясняет. Ниже — новые срезы `F*`
(финансы) поверх уже сделанных срезов 3/4/11/12, массовая интеграция донор-функций и
продуктовая линза. Работа продолжается по тем же правилам §1 (push после каждого среза).

### Континуитет при смене модели (важно)
Владелец переходит на **Sonnet** (`/model` → Sonnet 5). Вся «логическая связь на материал»
живёт в закоммиченных доках — их читает любая модель на старте сессии, нить не теряется:
план (этот файл) · леджер (PROGRESS.md) · каталог функций (docs/DONOR_FUNCTION_CATALOG.md,
160+ функций) · очередь (docs/INSIGHT_IMPLEMENTATION_QUEUE.md) · решения (DECISIONS.md) ·
уроки (LESSONS.md). Правило: перед сменой модели — commit+push (сделано); после — новая
модель начинает с чтения PROGRESS.md → раздела §4 здесь.

### A. Финансы-автосистема (срезы F1–F7) — приоритет «начать пользоваться»
Что уже есть (не переделывать, расширять): срез 3 — фраза→доход/расход, смена (часы,
доход/час, недельная цель), графики; срез 12 — «стоит ли завтра работать» на цифрах смен.

- **F1 — Банк-коннект честным гейтом.** Паспорт провайдера «Банк» со статусами
  `not-connected` / `permission-required` / `provider_unavailable` (НИКОГДА не имитировать
  успех — §7). Реальное подключение = данные владельца/OAuth, owner-gated. Честная локальная
  замена сразу рабочая: импорт выписки **CSV/OFX** файлом → строки (дата/сумма/описание).
- **F2 — Автосбор транзакций из выписки.** Парсер CSV/OFX (правила/regex сначала, как U2) →
  предложения (proposal перед записью) → финзаписи с категориями; дедуп по дате+сумме+описанию
  (донор Mem0/E1). Массовый импорт 20–30+ строк за раз (тот же паттерн, что дамп файлов).
- **F3 — Интеллект дохода.** Доход/час по сменам и по дням; «стоит ли ехать на работу»
  (сравнение дохода/час конкретной смены со средним/целью/альтернативой); тренд «час дороже/
  дешевле». Расширяет срез 3/12, честная арифметика.
- **F4 — Движок финцелей.** Цель «заработать X к дате» → прогресс + прогноз достижения по
  текущему темпу + инсайт «успеваешь/отстаёшь на Y». Проекция цели в артефакт и граф.
- **F5 — Визуализация (chart.js, уже одобрен).** Cash-flow по дням, доход/час, прогресс к
  цели, категории трат, «календарь-тепловая карта» заработка. Данные ≠ представление (§6).
- **F6 — Финансовые инсайты (Insight Engine).** Повторяющиеся траты, аномалии, «по этим дням
  недели тратишь больше», забытые подписки, «доход просел N недель» → Insight-артефакты с
  источниками и объяснением. Ложится на очередь I*/M1 (скоринг важности).
- **F7 — Связи финансов в графе.** Смена↔доход↔место работы↔часы↔цель↔человек как рёбра
  графа; переходы человек→смены→доход→цель (донор Neo4j/Graphiti — рёбра как проекция, не
  скрытая мутация; связывать через proposal/receipt).

### B. Массовая интеграция донор-функций (не по одной — потоком)
Директива: «сразу сотни функций, фишек, визуалов, эффектов». Источник — уже собранный
`docs/DONOR_FUNCTION_CATALOG.md` (160+ функций, размечены ✅/🔸/⛔) и очередь
`INSIGHT_IMPLEMENTATION_QUEUE.md`. Правило масштаба: берём функции ПАЧКАМИ по модулю
(граф-инсайты I*, память M*, RAG R*, запросы Q*, визуал V*), каждая пачка = вертикальный
срез со своим гейтом и push. НЕ переносим чужой код/архитектуру — только принципы в наш
артефактный слой (§0, Canon §4). ⛔-функции (тяжёлый ML/облако/произвольный JS-рантайм) — не
берём без явного слова владельца. «Полностью перепиши, у них другие системы» = реализуем
идею заново на нашем стеке, а не адаптируем чужой рантайм.

### C. Продуктовая линза «боль → вау → желание» (гейт каждого среза)
Владелец: реализовать то, «от чего появляется эффект вау и желание, когда боль закрывается».
Каждый срез проходит продуктовую проверку перед «готово»:
1. **Боль** — какую конкретную боль владельца закрывает (одна фраза). Нет боли → не делаем.
2. **Вау за ≤1 экран** — результат виден и ощущается сразу, без настройки и обучения
   (capture-first, прогрессивное раскрытие §6). Скучная форма ≠ вау.
3. **Желание вернуться** — что тянет открыть завтра (resurfacing/инсайт/прогресс к цели).
Эта линза — не маркетинг, а критерий, что функция «наполнена смыслом», а не ради счётчика.
