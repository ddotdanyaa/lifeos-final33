# LifeOS v1.4 — FULL_BUILD_PLAN (полная реализация вертикальными срезами)

Владелец (2026-07-20, вторая директива дня): «Весь скоуп — в один промпт. Но два правила
внутри оставил: порядок сборки и обязательный push после каждого блока. Работа без push в
репо не существует.» Плюс: «Перестрой план, чтобы всё на Fable переделал, и пиши дальше на
нём». Этот план ЗАМЕНЯЕТ очередь v1.3 после V0.5 (закрытые V0/V0.5 остаются в истории;
V1 CHAT_BRAIN заморожен как WIP и становится частью среза 5; V2-V5 из v1.3 растворяются в
срезы ниже — их спеки-заготовки переиспользуются, не выбрасываются).

## 0. Архитектурный закон (без изменений с v34-канона, подтверждён владельцем)

- **Single Source of Truth**: любой вход (текст, голос, фото, файл, транзакция, событие)
  становится АРТЕФАКТОМ. Все экраны — чат, дашборд, граф, финансы, таймлайн, агенты —
  только проекции слоя артефактов/сущностей/связей. Никаких модулей с собственным
  состоянием.
- **Local First**: всё возможное локально (Ollama, whisper.cpp). Cloud — только по явному
  выбору (API-ключ в настройках; BYOK-vault уже есть с P5.2).
- Стек не меняется: vanilla JS (ESM) + IndexedDB, живая оболочка `ui/*.js`, ядро `app.js`.

## 1. Правила выполнения (нарушение = стоп; слова владельца)

1. После КАЖДОГО среза: `npm run stamp` → git commit + push в текущую ветку + обновить
   `PROGRESS.md` + инструкция «как проверить за 60 секунд».
2. Срез не завершён, пока не работает в UI end-to-end. Заглушки, TODO, моки = не завершён.
3. Работа без push в репо не существует. «Готово» без коммита не принимается.
4. Блокировка → запись в BLOCKED.md, идти дальше.
5. Функции не ради количества: всё встраивается в единый слой артефактов, а не живёт
   отдельным экраном.
6. **Диета процесса** (из той же директивы): смоук — на каждый коммит; полный e2e — раз в
   день или перед пушем среза, НЕ после каждого изменения (флейки этой сессии — от
   resource contention при параллельных тяжёлых прогонах, трижды подтверждено); скриншоты —
   только при UI-изменениях; DECISIONS.md — одна запись на срез или реальную находку.
7. Хеш сборки: `npm run stamp` пишет git-hash в `index.html` (виден в шапке UI,
   `data-testid="build-version"`) и в имя SW-кэша (`service-worker.js`) — новая сборка
   гарантированно инвалидирует старый кэш. Если владелец видит «не ту» версию — первым
   делом сверить хеш в шапке с последним коммитом.

## 2. Порядок сборки (обязателен; статус аудита на 2026-07-20)

Каждый срез = работающий в UI функционал. «Есть» = реально работает и покрыто e2e сейчас.

### Срез 1 — Аудит кода → план переиспользования ✅ (этот документ + PROGRESS.md)

Итог аудита — что УЖЕ есть и переиспользуется (не переписывать с нуля):
- **Ядро артефактов**: 47 коллекций (`artifact-os-architecture.mjs` — исполняемый
  контракт), `sources`+`notes`+receipts/audit-трейл; происхождение частично (checksum,
  sourceId-связи, analysis); lifecycle через status/parserStatus. Артефакты НЕ иммутабельны
  формально — это гэп среза 2.
- **Universal Capture**: `analyzeArtifactInput` (текст/файл/аудио/фото/ics/eml/книги),
  proposal-first пайплайн, 4 быстрых действия на Дом (U1), голос end-to-end (whisper.cpp,
  U3), OCR-гейт (tesseract). Сущности частично: деньги/даты/время/wikilinks — да;
  люди/места/проекты — НЕТ (гэп среза 2/10).
- **Финансы**: транзакции/счета/бюджеты/подписки/недельный chart.js график/ввод одной
  фразой («350 бензин», U2). Отчёты через чат — WIP (заморожен V1). Прогноз/кэш-флоу — нет
  (срез 3).
- **Такси/смена**: доход/расход парсится; метрик смены (часы, доход/час, прогресс к
  недельной цели) НЕТ — ядро среза 3.
- **Чат**: Ollama live + честный локальный fallback + proposal на каждое сообщение (U4);
  WIP из V1 (закоммичен, НЕ доведён): RU-промпт с граф-контекстом, честные цитаты,
  вопрос≠заметка, идентичность модели из state. Срез 5 доводит и проверяет живым демо.
- **Голос**: whisper.cpp работает end-to-end (запись→расшифровка→заметка+связи, U3).
  Vosk честно заблокирован (BLOCKED.md). Эмоции/теги/люди из транскрипта — нет (срез 6).
- **Память 4 слоя**: НЕТ как модели. Есть: полнотекст `searchNotes`, semantic index
  (заблокирован ONNX — BLOCKED), minisearch установлен и НЕ используется. Срез 8.
- **Граф**: cytoscape (canvas, не DOM), названия узлов есть, причины рёбер есть, фильтры/
  локальный режим есть. «Уровень Obsidian» (карточка по клику, назад-навигация, плавность
  на сотнях узлов) — частично, срез 7.
- **Timeline**: лента `lifeFeedEvents` есть; единой оси с реконструкцией дня нет (срез 9).
- **Entity Resolution**: НЕТ («Данил»=«Даня» не склеивается). Срез 10.
- **Утро+вечер**: НЕТ (вечерняя сводка была V5 в v1.3 — спека готова, срез 11 её
  поглощает; утренней не было вовсе).
- **Insight Engine**: точечные rule-based `ensureInsight` есть; движка с ночным пересчётом
  нет. Срез 11.
- **Confidence/Explainability/User Model/Decision Support**: НЕТ. Срез 12. (Confidence
  частично есть у proposals.)
- **Agent Center**: `agentRuns`/flows/dry-run/kill-switch/бюджеты есть (P4.x). Срез 13 —
  доводка UI делегирования, не постройка с нуля.
- **Adaptive Dashboard**: `designStudio`/`designProfiles` частично; скрыть/переместить/
  размер — нет. **Инструкции пользователя** — нет. Срез 14.
- **Техбаза**: 64 e2e-спека, 24+ аудитов, гейты CLAUDE.md §4; премиум-редизайн V0.5;
  известные среды-флейки: реальные сетевые/модельные вызовы под параллельным прогоном

  задокументированы), спокойно перепрогонять изолированно.

### Срез 2 — Artifact Core + текстовый capture
Есть почти всё; добрать: (а) формальная иммутабельность артефактов-источников (правка =
новая версия/receipt, не мутация контента), (б) поле происхождения (`origin`: рука/голос/
файл/импорт/агент) на source, (в) сущности `people[]`/`places[]` в analysis (минимум:
заглавные слова + словарь владельца), (г) 60-сек проверка.

### Срез 3 — Финансы + такси + проекции
Смена одной фразой («отработал 12 часов, заработал 8700, бензин 1900») → предпросмотр
разбора (часы/доход/расходы/дата) → подтверждение → артефакт + финзаписи. Виджет «Неделя»:
часы, доход, расход, остаток до редактируемой недельной цели, доход/час. Рабочие дни в
календаре. LLM-парсинг НЕ блокирует: сначала правила/regex (расширение U2-парсера), Ollama
— улучшение сверху.

### Срез 4 — Дашборд + утренняя сводка
При открытии: дата, день недели, до недельной цели X, открытые задачи, вчера. Только из
реальных данных среза 3, никаких заглушек. (Вечерняя сводка — срез 11, спека V5 уже есть.)

### Срез 5 — Чат + Ollama поверх реальных данных (разморозка V1 WIP)
Довести закоммиченный WIP: живое демо «сколько я заработал за неделю?» → верный ответ из
реальных транзакций; контекст-движок: активные проекты/люди/недавние события в промпте;
гейт-спека `chat-brain-graph-context.spec.mjs` (уже написана) — прогнать против живого
даемона; вопросы БЕЗ мусорных цитат и без «сохранить заметку».

### Срез 6 — Whisper + голосовой пайплайн
Есть ядро; добрать: голос → полный capture-пайплайн (сущности/задачи/люди из транскрипта
через существующий analyzeArtifactInput), надёжность ежедневного использования.

### Срез 7 — Граф (редизайн до уровня Obsidian)
Карточка по клику (инспектор уже есть — прокачать), назад-навигация, переходы
человек→встречи→идеи→финансы (появятся после среза 10), плавность на сотнях узлов.

### Срез 8 — Память + context engine + поиск
4 слоя (Active/Working/Long-term/Archive) как ВЫЧИСЛЯЕМАЯ проекция по возрасту/связности/
типу артефакта (не 4 хранилища — закон SSoT); minisearch наконец в дело; поиск по памяти
из чата.

### Срез 9 — Timeline
Единая ось: события, расходы, мысли, фото, смены; реконструкция любого дня (расширение
lifeFeedEvents + фильтр по дню).

### Срез 10 — Entity Resolution
«Данил»=«Даня»=«я» → один узел; при низкой уверенности — спросить (proposal-механизм уже
есть, переиспользовать).

### Срез 11 — Рефлексия + Insight Engine
Утро (срез 4) + вечер («подвести день?» → голос → разбор) + пересчёт закономерностей
(повторяющиеся траты/ошибки, забытые проекты, тренды) → артефакты типа Insight с
источниками. «Ночной» = при первом открытии за день (локальное приложение не живёт ночью).

### Срез 12 — User Model + Confidence + Explainability + Decision Support
Вычисляемые характеристики (дисциплина/ритм/энергия) из артефактов; каждый вывод с
уверенностью и раскрытием «почему/на каких данных/альтернативы»; «стоит ли завтра
работать?» на реальных цифрах смен.

### Срез 13 — Agent Center
Делегирование задач агентам поверх существующих agentRuns/flows: статус/прогресс/результат/
история в человеческом UI.

### Срез 14 — Adaptive Dashboard + Инструкции
Виджеты скрыть/переместить/размер (sortablejs уже в деле для календаря); правила поведения
системы от владельца + пресеты; дообучение через обратную связь = правила-артефакты.
