# LifeOS — режимы работы

LifeOS — статический vanilla JS PWA поверх `server.mjs` (простой Node HTTP-сервер, отдаёт файлы как есть, без API/бэкенда). Все данные хранятся в IndexedDB конкретного браузерного профиля на конкретном устройстве — сервер их не видит и не хранит. Ниже — три реальных способа запустить и использовать LifeOS, без выдумывания несуществующего облачного sync.

## Mode 1 — локально (по умолчанию)

Запуск на одном устройстве, для одного пользователя этого устройства.

```
npm start
```

Открывает `http://localhost:4173` в браузере этого же компьютера. Данные живут в IndexedDB этого браузерного профиля. Закрыл вкладку — сервер можно останавливать, данные остаются на диске между запусками.

Это режим, в котором проверяются все гейты этой сессии (`npm run verify`, аудиты, e2e).

## Mode 2 — локальный демон (всегда запущен)

То же самое, что Mode 1, но `node server.mjs` держится как долгоживущий фоновый процесс на своей машине (через диспетчер процессов ОС, автозапуск или терминал, оставленный открытым), чтобы `http://localhost:4173` был доступен без ручного `npm start` каждый раз.

Отличие от Mode 1 — только в том, как запущен процесс, не в архитектуре. Данные всё ещё живут в IndexedDB того же браузера на той же машине; демон не добавляет sync между устройствами и не открывает доступ извне.

## Mode 3 — домашний сервер через LAN

`server.mjs` не биндится специально на `127.0.0.1` — Node слушает на всех интерфейсах по умолчанию, поэтому один и тот же процесс уже доступен другим устройствам в той же локальной сети по LAN-адресу хоста:

```
node server.mjs
# на других устройствах в той же сети:
http://<LAN-IP-этой-машины>:4173
```

**Честная граница этого режима:** LifeOS не синхронизирует данные между устройствами. Каждое устройство, которое открывает этот адрес, получает тот же самый код приложения, но пишет в **свою собственную** IndexedDB — это не общая база, а независимые копии одного и того же приложения. Совместное использование одного набора данных с нескольких устройств через Mode 3 сейчас не реализовано и не заявляется как рабочее; это тема post-v1 (см. §8 мастер-плана).

**Безопасность LAN-режима:** `server.mjs` не делает аутентификацию и не шифрует трафик — открывать порт 4173 стоит только в доверенной домашней сети, не через port-forwarding в интернет.

## Что не входит ни в один режим

- Никакого облачного backend, никакой синхронизации между устройствами «из коробки».
- Никакого скрытого сетевого вызова: единственные внешние обращения — к явно настроенному владельцем Ollama-демону (Mode 1/2/3 не влияют на это) и к BYOK cloud-маршрутам, которые требуют явного ключа и подтверждения на каждый вызов.
