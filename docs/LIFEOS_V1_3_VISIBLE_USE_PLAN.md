# LifeOS v1.3 — VISIBLE_USE_PLAN («видимый спектр»)

Владелец (2026-07-20): «Хочу тестировать: накидывать кучу мыслей, чтобы из них создавались
графосвязи, чтобы инсайты появлялись, чтобы я мог проект новый создавать. Мне нужно
ПОЛЬЗОВАТЬСЯ сейчас. Либо всё в видимом спектре, либо ничего. Бери готовые репозитории,
перестраивая под артефактную систему. Сделай готовую почву для Sonnet.»

Этот план написан после изучения архива истории проекта (`LIFEOS.7z`: каноны 15%→33%,
Notion/n8n-прототипы, Next.js-сборка и её FAILED_PATTERNS_REGISTRY) и разбора живого
скриншота владельца от 2026-07-20 (чат отвечает по-английски с мусорными «источниками»).
Он ЗАМЕНЯЕТ очередь v1.2 после U5 (U6 переносится сюда как V5). Порядок пакетов строгий:
V0 → V0.5 → V1 → V2 → V3 → V4 → V5 (V0.5 — визуальный редизайн, вставлен владельцем в
эту же сессию между V0 и V1). Дисциплина исполнения — как во всех прошлых планах:
commit+push после каждого пакета, спорное — самостоятельно в DECISIONS.md, блоки — в
BLOCKED.md и продолжать.

## 0. Диагноз скриншота владельца (по коду, не по догадкам)

Владелец спросил чат: «Ты умеешь давать инсайты по всем связям в графе? Какого уровня ты
модель?» и получил: английский ответ «As a text-based assistant, I don't have insights…» +
«Источники: Свои API-ключи, 2+2 ПОСЧИТАТЬ СЕГОДНЯ, СЕГОДНЯ В 4 В ШИНОМОНТАЖ» + предложение
«ЗАМЕТКА: Сохранить источник в библиотеку» на сам вопрос. Причины найдены в app.js:

1. **Ollama РЕАЛЬНО подключена и ответила** (статус `generation_ok` — живая петля есть,
   это хорошая новость). Но `buildOllamaChatPrompt` (app.js:7888) написан по-английски и
   НЕ требует отвечать по-русски → маленькая локальная модель зеркалит язык промпта.
2. Промпт даёт модели ТОЛЬКО «Active context» (одна заметка/источник) + 3 наивных
   поисковых попадания. **Графа в промпте нет вообще** — модель честно говорит «не имею
   доступа к графу», потому что это правда. При этом в приложении есть настоящий граф с
   причинами рёбер (`edgeReasons`, `selectedGraph`, backlinks из R3) — данные есть, в
   промпт они не попадают.
3. «Источники» — это `searchNotes(state, вопрос).slice(0,3)` (app.js:15433): наивный
   keyword-поиск по тексту вопроса. Для вопроса со словом «сегодня» он выдал случайные
   задачи. Цитаты приклеиваются безусловно (app.js:15461) — выглядит как мусор/театр.
4. `createChatMessageProposal` (app.js:5006) гонит КАЖДОЕ сообщение владельца через
   `analyzeArtifactInput` — вопрос ассистенту классифицируется как «заметка, сохранить в
   библиотеку». Вопросы не должны порождать предложение «сохранить сам вопрос».
5. Жёсткий лимит «max 40 words» в промпте (введён для CPU-таймаутов) гарантирует, что
   ЛЮБОЙ ответ выглядит глупо. Для инсайт-вопросов нужен другой бюджет.

Всё это — пакет V1. Ни один пункт не требует новых зависимостей.

## 1. Смена стратегии: правило видимого спектра

Из FAILED_PATTERNS_REGISTRY самого владельца (Next.js-эпоха, найден в архиве):
- **FP-004**: «шаг не закрыт по lint/build/diff/красивому summary — нужен runtime-proof
  затронутого сценария». Здесь ужесточается: runtime-proof = e2e + пара скриншотов
  до/после В СЦЕНАРИИ ВЛАДЕЛЬЦА (не в синтетическом).
- **FP-006**: «один проход = один слой». Пакеты ниже нарезаны по этому правилу.

Новые правила этого плана (обязательные):
1. **Каждый пакет обязан менять то, что владелец видит в первые 30 секунд использования
   своего сценария.** Пакеты «внутренней механики» запрещены, пока очередь V0–V5 не пуста.
2. **Сценарий владельца — единственный гейт-сценарий**: «накидал мысли → увидел связи →
   получил инсайт → создал проект → вечером сводка». Каждый пакет закрывает свой шаг этой
   цепочки и прогоняется e2e именно по нему.
3. **RU-only во всём видимом**: ни одной английской строки в ответах чата, инсайтах,
   подписях. `audit-primary-ui-language.mjs` уже есть — расширить его на тексты ответов.
4. **Скриншоты до/после** в `docs/qc/screens/<пакет>/` — как в v1.2 §0, без изменений.

## 2. Про «готовые репозитории» — честная рамка (не обещать невозможное)

Что УЖЕ реально взято готовым и работает: whisper.cpp (целиком, официальный prebuilt
релиз, MIT — расшифровка голоса), pdfjs-dist, chart.js, fflate, sortablejs, cytoscape,
dompurify, marked, tesseract, transformers.js — 12 движков в рантайме. Что НЕЛЬЗЯ взять
целиком: Logseq (AGPL — только идеи), Obsidian (закрытый), LobeChat/Jan (Apache, но это
React/Next/Tauri-приложения — их код физически не вставляется в no-build vanilla ESM без
переписывания, что дольше, чем портировать алгоритм). Поэтому «беру готовый репозиторий» в
этом стеке значит одно из двух, и в каждом пакете ниже указано, что именно:
- **вендорить библиотеку целиком** (как whisper.cpp), если она самодостаточна и MIT/Apache/BSD;
- **портировать конкретный алгоритм/паттерн** из именованного permissive-репозитория с
  указанием файла-источника в комментарии и DECISIONS.md.

Уже установлено и НЕ используется (использовать в первую очередь, прежде чем что-то новое):
`minisearch` (MIT, полнотекст/токенизация — ядро V2), `epubjs` (решение по U5 в
DECISIONS.md — не понадобился), `@huggingface/transformers` (заблокирован ONNX — не трогать).

### V0.5 UI_PREMIUM_REDESIGN (владелец потребовал в этой же сессии, между V0 и V1)

Цель: владелец прямым текстом потребовал «уровень Linear/Raycast/Notion AI, дорогой SaaS,
premium spacing, современные карточки» и явно сказал использовать frontend-design skill
(недоступен в этой сессии — не в списке доступных скиллов; сделано экспертной ручной
CSS-работой). Чисто визуальный слой (только `styles.css`) — функциональность и архитектура
не тронуты, это оправдывает вставку вне очереди V1-V5 как отдельный "один слой" (FP-006).

- Токены: новая шкала теней (`--shadow-card/--shadow-float/--shadow-modal`, многослойные,
  не одна размытая), `--ease` (кривая анимации), `--focus-ring`, `--bg-surface-2`/
  `--bg-surface-hover` (уровень вложенности для секций внутри карточек).
- Навигация: плоские пункты меню без рамок, активный пункт — синяя левая полоска +
  подсвеченный фон (Linear-паттерн), а не "кнопка с рамкой".
- Кнопки: primary — синий акцент вместо чёрного, ghost/danger — приглушённые прозрачные
  фоны вместо сплошных плашек, честный focus-ring.
- Карточки/строки: единый рецепт (hairline-бордер + `--shadow-card` вместо жирной рамки +
  большой размытой тени), вложенные секции на тон темнее внешней карточки.
- **Найден и исправлен реальный баг, не связанный с версткой**: в комментарии U0-токенов
  (styles.css, самое начало файла) буквально встречалась последовательность символов
  «звёздочка+слэш» внутри прозаического текста («--color-*/--paper/») — это настоящий
  CSS-токен закрытия комментария, поэтому комментарий закрывался на три строки раньше
  положенного, и парсер съедал следующее объявление (`--text-xs`) при попытке восстановиться.
  Тот же баг я по неосторожности повторил в своём новом комментарии дальше по файлу — там
  жертвой стал ЦЕЛЫЙ блок `:root { --bg-app: ...; --accent-capture: ...; }` (19 свойств),
  из-за чего тёмная тема почти ничего не меняла с самого пакета U0 (все `--bg-*`/`--text-*`
  токены, которыми реально пользуется весь видимый интерфейс, не имели тёмного варианта
  вообще — только СТАРЫЙ набор `--paper/--surface/--ink`, которым почти никто не пользуется).
  Найдено через `document.styleSheets`/CSSOM-диагностику в браузере, а не догадкой.
- Тёмная тема: добавлен полноценный `:root[data-theme="dark"]` для `--bg-*`/`--text-*`/
  `--line-soft` (был пробел с U0) + точечные фиксы для мест с зашитыми светлыми цветами,
  которые эта тёмная тема сразу же обнажила (Финансы: карточка баланса/бюджета/счетов/
  недельный график; Чат: панель контекста ответа и вложенные provider-статусы; Календарь:
  вкладки/почасовая сетка/тайм-блоки; Граф: подписи колеса баланса; мобильная нижняя нав-
  панель; общие `.v34-form`/`.v34-boundary-grid`). Ридер намеренно оставлен тёплым
  "бумажным" (со своим тёмным сепия-вариантом), а не переведён на нейтральный серый —
  осознанный дизайн-выбор для длинного чтения, не недосмотр.
- **Гейт**: `node --check`-эквивалент для CSS (баланс `{`/`}`), `audit-semantic-colors`,
  `audit-visual-hierarchy`, `audit-home-complexity`, `smoke.mjs` — все зелёные. Визуальная
  проверка через Playwright-скриншоты (браузерная панель зависала на screenshot в этой
  сессии — не связано с CSS, задокументировано отдельно) в light И dark на Дом/Сегодня/

### V1 CHAT_BRAIN (чат отвечает по-русски, про НАСТОЯЩИЙ граф, без мусора)

Цель: тот самый скриншот больше невозможен. Каждый пункт §0 закрыт.

- **V1.1 RU-промпт с контекст-паком**: переписать `buildOllamaChatPrompt` — инструкция
  по-русски, требование отвечать ТОЛЬКО по-русски; в промпт включить честный контекст-пак:
  (а) цифры графа (узлы/рёбра/топ-хабы по степени — всё уже считается для Графа),
  (б) окрестность выбранного узла с ПРИЧИНАМИ рёбер (`edgeReasons` уже существуют),
  (в) сводка дня (задачи/деньги — как U1/U6 уже агрегируют), (г) активный артефакт.
  Паттерн контекст-пака — из LobeChat (Apache-2.0, идея «structured context injection»),
  портирование, не копирование.
- **V1.2 Честные цитаты**: цитировать ТОЛЬКО артефакты, реально вошедшие в промпт, с
  порогом релевантности; для мета-вопросов («какая ты модель») — без цитат вообще.
  Вопрос о модели отвечать из `state.ollama.selectedModel` (это факт приложения, а не
  фантазия LLM): «Локальная модель X через Ollama».
- **V1.3 Вопрос ≠ заметка**: детектор вопроса (?, «ты умеешь», «как», «что», «почему»,
  «сравни»…) в `createChatMessageProposal` → на вопросы предложение не создаётся.
- **V1.4 Бюджет ответа по типу вопроса**: быстрый вопрос — короткий бюджет (как сейчас);
  инсайт/обзор («инсайты», «связи», «итог», «проанализируй») — увеличенный num_predict и
  промпт без «max 40 words». Таймауты уже щедрые (150s) — не трогать.
- **Гейт**: e2e с живым Ollama: RU-вопрос «какие связи и инсайты по графу?» → RU-ответ,
  содержащий реальные цифры графа из состояния; никаких английских ответов; никаких
  цитат-задач; на вопрос нет предложения «сохранить заметку». Скриншоты Чат до/после
  (до = воспроизведённый скриншот владельца).

### V2 THOUGHT_STREAM (накидал мысли → увидел связи)

Цель: главный сценарий владельца — брейндамп. Сейчас каждую мысль надо вводить отдельно,
и связи между мыслями появляются только через wikilinks/общую заметку.

- **V2.1 Поток мыслей**: многострочный ввод на Дом/Лента («вставил 10 строк → 10
  артефактов» одним действием, каждый через существующий `captureTextArtifact`).
- **V2.2 Автосвязи с причинами**: первый реальный запуск `minisearch` (MIT, установлен,
  не используется): токенизация RU/EN, топ-K значимых термов на артефакт (TF-IDF),
  связь между артефактами при ≥2 общих термах; причина ребра = сами термы («общие темы:
  бензин, машина»). Паттерн — backlink/unlinked-references из Foam (MIT) и graph-плагина
  Quartz (MIT), алгоритм портируется, рендер — существующий cytoscape-граф. НИКАКОЙ
  скрытой AI-мутации: связи — это факты о тексте, создаются синхронно и видимо, с
  receipt в Data Control (соответствует CLAUDE.md §7).
- **V2.3 Панель «Связи» на заметке**: у каждого артефакта видимый блок «с чем связано и
  почему» (расширение backlinks-панели R3 причинами рёбер).
- **Гейт**: e2e — вставить 10 разноплановых мыслей → в состоянии ≥N автосвязей с
  внятными причинами; Граф показывает кластеры; скриншоты Лента+Граф до/после.

### V3 INSIGHT_FEED (инсайты появляются сами и честно)

Цель: «чтобы инсайты могли появляться». Два яруса, оба с источниками-пруфами:

- **V3.1 Структурные инсайты (без AI, всегда работают)**: хабы («7 мыслей за неделю
  крутятся вокруг Машины»), новые кластеры («эти 4 мысли связались за сегодня»),
  повторяющиеся темы по дням, деньги↔задачи. Каждый инсайт = существующий `ensureInsight`
  с перечислением конкретных артефактов-источников. Показывать на Дом/Лента.
- **V3.2 AI-инсайты (только при Ollama, только через proposal)**: раз в запрос владельца
  («Найди инсайты») модель получает V1-контекст-пак и предлагает инсайт-карточки;
  применение — через существующий proposal-механизм (AI_MEMORY_GATE уже это требует).
- **Гейт**: e2e — после V2-брейндампа ≥3 структурных инсайта с реальными источниками;
  с Ollama — AI-инсайт создаётся только после «Применить». Скриншоты Дом до/после.

### V4 PROJECT_LOOP (мысль → проект в один клик)

Цель: «чтобы я мог проект новый создавать» из потока, а не через формы.

- Кнопка «В проект» на мысли/инсайте/чат-сообщении → создаёт проект (коллекция
  `projects` уже есть), привязывает исходный артефакт и всё связанное с ним по V2-рёбрам
  (с предпросмотром: «взять эти 4 связанные мысли? да/нет» — не скрытая мутация).
- Вид проекта: его артефакты, его задачи, его подграф (фильтр существующего Графа по
  связям проекта).
- **Гейт**: e2e — из брейндамп-мысли создать проект, 2 связанные мысли подтянулись после
  подтверждения, подграф в Графе отфильтрован. Скриншоты до/после.
