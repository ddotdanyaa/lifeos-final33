# Бриф: кто что имеет право писать (governance)

Когда над репозиторием работают владелец, петля самоулучшения, планировщик, исполнитель и
параллельная сессия, «все могут всё» означает, что никто ни за что не отвечает. Эта таблица —
не бюрократия, а способ сделать нарушение **видимым**.

## 1. Таблица прав

| Кто | Может писать | Не может ни при каких условиях |
|---|---|---|
| **Владелец** | всё | — |
| **Петля самоулучшения** (О-пакеты) | `state.decisions`, `state.surfaceUsage` — и только их | код, спеки, аудиты, данные владельца, политику весов без внешнего вердикта |
| **Планировщик** (Fable) | план, очередь пакетов, брифы | код и гейты; **репозиторий не открывает** — читает `docs/context/*.brief.md` |
| **Исполнитель** (Claude Code) | код продукта, НОВЫЕ спеки, доки | существующие утверждения в гейтах; `smoke.mjs`; тестовые скрипты `package.json` |
| **Параллельная сессия** | свою ветку | файлы чужого пакета; `app.js` одновременно с другой сессией без сверки |
| **Диспетчер** (3.1) | ветку пакета, PROGRESS.md | merge без зелёного; работу вне окна и бюджета |

## 2. Три правила, из которых всё выводится

**И-1. Судья всегда вне петли.** Система никогда не решает сама, что стала лучше. Вердикт даёт
владелец или внешний факт, и только он двигает веса.

**И-2. Память ≠ политика.** Накопить доказательство и сменить правило — РАЗНЫЕ операции.
Накопление идёт автоматически, смена правила — никогда.

**И-8. Гейт не чинится вместо кода.** Проверяется машиной: `tools/audit-no-gate-tampering.mjs`
читает дифф пакета и различает три случая — новая спека (работа), дополненный гейт (проверок
стало больше), удалённое утверждение (**подделка, пакет отклонён независимо от цвета гейтов**).
У `smoke.mjs` правило строже: он список маркеров, там утверждение выглядит обычной строкой, и
удаление любой содержательной строки считается ослаблением.

## 3. Чем каждое право проверяется

| Право | Инструмент |
|---|---|
| гейты не ослаблены | `tools/audit-no-gate-tampering.mjs` |
| брифы не отстали от кода | `tools/audit-context-freshness.mjs` |
| ссылки на доноров не врут | `tools/audit-donor-links.mjs` |
| мёртвого кода не стало больше | `tools/audit-dead-code.mjs` |
| форма продукта не поехала | `audit-workspace-shape`, `audit-seven-contracts` |
| ничего не делается молча | `audit-no-label-theater`, `control-routes-receipts` |
| петля не выдаёт догадку за знание | `decisions-become-calibration` (порог 8 решений, дрейф, затухание) |

## 4. Что делать при конфликте прав

Пример из этой сессии: **П2 требовал расширить `audit-no-label-theater`**, а П25 запрещает
пакету трогать аудиты. Разрешение: расширение (только добавленные строки, проверок стало
больше) — не подделка, и аудит это различает автоматически. Ослабление осталось бы красным.

Второй пример: **`money-fast-capture.spec.mjs` ходил в пункт меню «Привычки»**, который прошлый
коммит намеренно слил с «Целями». Спека пошла за продуктом — это законно, но обязано быть
названо в отчёте, а не пройти молча.

Третий, разрешённый наполовину: мёртвый код удалён там, где его ничто не держало (102 функции /
2342 строки), и **не тронут там, где его держат гейты** — 35 функций / 1182 строки. Их удаление
требует правки `smoke.mjs` и аудитов, то есть выхода за право исполнителя. **Решение владельца.**

Четвёртый, купленный ошибкой: аудит мёртвого кода сначала читал ЧЕТЫРЕ гейта из тридцати —
список был написан по памяти. Массовое удаление по нему уронило три аудита и съело живую
функцию. Правило после этого: **гейт — это любой `tools/audit-*.mjs`**, и удаление идёт по
одной функции с проверкой после каждой, а не пачкой.

## 5. Открытые долги

- Диспетчера (П27) нет: запуск пакета — ручное действие владельца.
- Калибровки приёмки (П29) нет: политика авто-слияния по типам с точностью ≥95% не считается.
- Цена за принятый пакет (П30) в леджер не пишется.
