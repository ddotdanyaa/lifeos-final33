# Бриф: провайдеры и локальные движки (providers)

Всё, что LifeOS вызывает снаружи себя: расшифровка речи, локальная модель, OCR, парсеры книг,
уведомления, внешний календарь. Общий закон один и он не обсуждается: **провайдер честен**.
Статус бывает `ok` / `not-connected` / `permission-required` / `provider_unavailable` — и никогда
не бывает имитации успеха.

## 1. Расшифровка речи — три пути, один результат

| путь | где живёт | когда |
|---|---|---|
| **whisper.cpp** | локальный сервер `http://127.0.0.1:8090/inference` | основной |
| **Whisper (transformers.js)** | Web Worker, веса с HuggingFace CDN | без демона |
| **Vosk** | `vosk-browser`, модель small-ru | запасной |

Все три заканчиваются одним вызовом `saveSourceTranscript(state, sourceId, text, options)` —
дальше расшифровка живёт одинаково независимо от движка. Один провенанс, один путь.

**Модель выбирается замером, а не названием.** На процессоре владельца (замер 2026-07-28):
`ggml-base` — быстро, но каша без пунктуации, разбору нечего брать; `ggml-large-v3-turbo` —
2 мин 15 с на 11 секунд звука, непригодно; `ggml-small` — **22 секунды**, текст и пунктуация как
у большой. Выбран `small`, `npm run whisper-server` указывает на него.

**`verbose_json`, а не `json`** (П5): тот же текст плюс сегменты с настоящими секундами
(`start`/`end`). Без них обратный путь «вывод → цитата → место в записи» пришлось бы угадывать.

**Мост в 16 кГц моно** (`decodeAudioTo16kMono` + `encodeWav16kMono`) стоит перед отправкой:
телефонная запись возвращалась в 5,5 раза тяжелее нужного.

**Паузы говорящего — границы смысла.** whisper отдаёт речь построчно; `cleanTranscript`
сохраняет переводы строк, `cleanLine` их схлопывает. Перепутать — значит превратить двадцать
минут речи в одну задачу с названием во весь экран (случалось).

## 2. Ollama (локальная модель)

`state.ollama`: `endpoint` (`http://127.0.0.1:11434`), `selectedModel`, `status`, `models`,
`lastError`, `lastLatencyMs`.

Подключение считается настоящим только после ДВУХ явных проверок: `/api/tags` (модели видны) и,
отдельно, тест генерации `/api/generate`. Наличие демона само по себе ничего не доказывает.

Применения: чат (`streamOllamaChatAnswer`, NDJSON-поток), разбор речи в намерения
(`requestSpeechIntentsFromModel`, за флагом `speechIntents`, по умолчанию выключен).

**Что показал замер (2026-07-28, эта машина):** `qwen2.5:3b` — 44 секунды на одну надиктовку и
частично сломанный JSON; `qwen3:4b` — 99 секунд и пустой ответ (бюджет `num_predict` съеден
рассуждениями). Вывод в архитектуру: **правила первичны, модель добавляет непонятое**, её ответ
проходит тот же валидатор с обязательной цитатой из слов владельца.

**Граница доверия (3.1d).** Текст источника — ДАННЫЕ, не команды: подаётся в промпт только
размеченным блоком, и модели прямо сказано, что инструкций внутри него нет.

**`<think>`-блоки** вырезаются (`stripModelThinkingBlocks`): владелец не должен видеть черновик
рассуждений вместо ответа.

## 3. Разрешения (capability grants)

Грант — это `resource + action + scope + locality + approval + budget`. Каждое действие
провайдера проверяет грант ПЕРЕД запуском и пишет `recordProviderRun`. Контейнер разрешений
может отсутствовать в снимке от старой версии — доступ только через `capabilityStore`
(именно необорудованный доступ к `state.control.capabilities` однажды уронил загрузку и привёл
к потере данных, см. бриф `storage-kernel` §3).

## 3.1. Что провайдер оставляет петле

Каждое предложение, рождённое намерением из речи, несёт `origin` — правило или модель. Журнал
решений (`docs/context/self-improving-loop.brief.md`) пишет его на каждое решение владельца,
поэтому точность правил и точность модели считаются ОТДЕЛЬНО. Мерить их вместе значит не узнать
про обе — а замер 2026-07-28 показал, что на этой машине правила сильнее.

## 4. Границы

- Ни одного скрытого сетевого вызова. Веса моделей качаются только после явного клика владельца.
- Ключи, учётки, CAPTCHA вводит только владелец.
- Падение провайдера не роняет платформу: разбор по правилам уже отработал.

## 4.1. Журнал прогонов ограничен

`recordProviderRun` пишет каждый вызов движка, и на тысяче расшифровок этот журнал весит больше
самих записей владельца. П22 обрезает его до 200 последних раз в сутки — остаются самые свежие,
по которым что-то понятно.

## 5. Ловушки среды (проверено болью)

- **Знак процента в пути ломает Playwright.** Проект лежит в `LIFEOS FINAL 33%`, и
  `setInputFiles(<путь>)` на таком пути МОЛЧА не прикрепляет файл. Выглядит как «плавающий»
  дефект приложения. Файлы в спеках передавать **только буфером**.
- **Первый тест в файле падает чаще прочих** — холодный старт браузера и установка service
  worker. Это не дефект продукта.
- Скачивание модели Whisper с HuggingFace в headless упирается в сеть и таймауты: спека
  `whisper-transcribe` красная по среде, а не по коду.

## 6. Как проверять изменения

`whisper-transcribe` · `voice-loop-whispercpp` · `voice-loop-vosk` · `m4a-voice-end-to-end` ·
`ollama-real-daemon` · `ollama-live-chat` · `byok-vault-routing` · `failure-injection` ·
`audio-any-format` · `audio-alac-decode`.

## 7. Открытые долги

- Слой намерений на модели проверяется только на машине владельца — метка
  **[ЛОКАЛЬНАЯ ПРИЁМКА]**.
- Мост Telegram (волна 5, П35) не начат; когда начнётся — второй путь импорта не строить,
  входить в существующий `importFilesFromInput`, транскрипцию оставить свою (провенанс один).
