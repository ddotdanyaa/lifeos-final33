## 1. Полный жизненный цикл мысли

Внешняя ревизия права: спека описывала вход и разбор, но не то, что с мыслью происходит потом.
Здесь — все переходы. Состояния совпадают с полями, которые в коде уже есть.

```
                   ┌──────────── правка ────────────┐
                   ▼                                │
пусто → черновик → разобрано → предложено → принято ─┴→ объект → связано → использовано
          │            │           │           │         │          │           │
          │            │           │           └─ отклонено          │           │
          │            │           │                  │              │           │
          │            │           └─ уточнение ──────┤              │           │
          │            │                              │              │           │
          └─ брошено   └─ не понято                   ▼              ▼           ▼
                          (сохранено как есть)     журнал        граф        память
                                                   решений                       │
                                                                                 ▼
                                                              архив → корзина(30 дн) → удалено
```

| Переход | Чем вызывается | Где в коде | Что видит владелец |
|---|---|---|---|
| пусто → черновик | набор текста | `state.captureDraft` | похожие прошлые появляются под полем |
| черновик → разобрано | «Разобрать» | `analyzeArtifactInput` `app.js:5148` | построчные выводы (Срез Б) |
| разобрано → предложено | рождение предложения | `addProposal` `app.js:6106` | строка + цитата + доверие |
| предложено → принято | своя кнопка строки | `applyProposal` `app.js:7812` | объект создан, видно куда |
| предложено → отклонено | «Не то» | `dismissProposal` `app.js:8777` | строка гаснет, вес пишется |
| принято/отклонено → журнал | **автоматически** | `recordOwnerDecision` `app.js:8204` | ничего — и это правильно |
| разобрано → уточнение | вердикт по похожей | тип `supersede` `app.js:7922` | старая помечена заменённой |
| объект → архив | ручное | — | восстановимо |
| архив → корзина → удалено | 30 дней | `TRASH_GRACE_DAYS` `app.js:20456` | «осталось N дней» |

**Дыра, которую видно на этой карте:** между «принято» и «использовано» нет ни одного измерения.
Система не знает, пригодился ли созданный объект. Закрывается ставками (`state.bets`), сейчас они
покрывают только `task-today` — см. документ 3.

## 2. Бюджет задержек — контракт

Числа не измерены на нашем железе (кроме расшифровки) — это **бюджет**, то есть обязательство.
Превышение бюджета без видимой реакции экрана считается дефектом, а не «так вышло».

| Порог | Что обязано появиться | Чего быть не должно |
|---|---|---|
| **до 100 мс** | ничего. Результат просто есть | индикатора нет — мигание хуже ожидания |
| **100–500 мс** | скелетон формы результата (серые полосы на месте будущих строк) | спиннера нет |
| **0,5–2 с** | скелетон + подпись **что именно делается**: «читаю запись», «ищу похожие» | «Загрузка…» без предмета |
| **2–5 с** | то же + кнопка «Отменить» | молчаливое ожидание |
| **5–15 с** | строка «это дольше обычного» + что уже готово частично | сброс экрана |
| **> 15 с** | уходит в фон, поле ввода **освобождается**, по готовности — строка «разбор готов» | блокировка ввода |
| **расшифровка голоса** | отдельный случай: «на этом компьютере это минуты, а не секунды» — формулировка уже принята в ledger №11 | ложное «почти готово» |

**Правило скелетона:** он повторяет **форму** будущего результата (три строки выводов), а не
абстрактный прямоугольник. Иначе экран дёргается при подстановке.

**Правило отмены:** отмена возвращает черновик целиком, включая прикреплённые файлы. Ничего
из наполовину разобранного не записывается — инвариант «нет скрытых действий» (CLAUDE.md §7).

## 3. Микровзаимодействия — по сценариям

Внешняя ревизия просила «магию»: 15–20 мелочей на сценарий. Ниже — только те, что реализуемы
в vanilla на существующих токенах, и каждая обязана что-то значить.

### С3 · найден дубль (сейчас в коде: список без реакции)

| # | Мелочь | Смысл |
|---|---|---|
| 1 | Похожие появляются **во время набора**, не после отправки | повтор не должен родиться |
| 2 | Появление — сдвиг сверху 40 мс, не мигание | мигание читается как ошибка |
| 3 | Наведение на находку подсвечивает **её дату** | владелец решает по времени |
| 4 | Клик открывает ту запись, не модалку | путь один: `open-source-note` |
| 5 | Вердикт — три кнопки в строке, не выпадающий список | одно движение |
| 6 | «Дубль» → находка уезжает вверх, поле очищается | мысль не родилась — правильный исход |
| 7 | «Уточнение» → у старой появляется полоса «заменено» | видно, что не расплодилось |
| 8 | «Новое» → блок похожих сворачивается до строки «проверено» | не мозолит |
| 9 | Любой вердикт → строка «учтено» с датой | обучение видно |
| 10 | Отмена вердикта доступна, пока запись на экране | ошибка исправима без Контроля |

### С2 · построчный разбор (Срез Б)

| # | Мелочь | Смысл |
|---|---|---|
| 1 | Каждый вывод растёт из цитаты по волосяной вертикали | основание физически видно |
| 2 | Наведение на вывод подсвечивает фрагмент в исходном тексте | связь двусторонняя |
| 3 | Уровень доверия — словами, число только внутри фразы | правило `ui/home.js:156` |
| 4 | Латунь только у измеренного доверия | «измерил» ≠ «предположил» |
| 5 | Принятая строка не исчезает — сворачивается в «создано: …» | видно, что получилось |
| 6 | Отклонённая гаснет до 40 % и остаётся до перезагрузки | случайное нажатие обратимо |
| 7 | Правка названия до принятия — прямо в строке | флаг `edited` — сильнейший сигнал |
| 8 | Выводов > 7 → «ещё N», без скролла | больше семи не читают |
| 9 | «Принять всё» — внизу, ghost-кнопкой | иерархия перевёрнута обратно |
| 10 | Ноль выводов → «я не понял ничего конкретного» + «сохранить как есть» | никогда не молчание |

## 4. Карта эмоций и точки раздражения

| Момент | Что чувствует | Что раздражает сейчас | Чем закрывается |
|---|---|---|---|
| 0–5 с, первый вход | «куда писать» | 10 кнопок вместо поля | Срез Г |
| 5–30 с, первая мысль | «оно поняло или сделало вид» | «источник сохранён, принять безопасные» | Срез Б |
| 30 с – 3 мин, разбор | «сколько ждать» | нет индикатора вовсе | §2 этого документа |
| Вечер первого дня | «что-нибудь накопилось» | дайджест не сведён | Срез Д |
| День 3 | «оно повторяет ту же ошибку» | профиль работает, но не виден | Срез А (сделан) + Д |
| День 7 | «стало ли лучше» | измерять нечем | документ 4 |
| Неделя 3 | «накопился мусор» | откатов всего 6 (`app.js:2556`) | документ 5 |

**Главная точка отказа — день 3.** Если к этому дню владелец не увидит **чему именно** система
научилась, он перестанет выносить вердикты, журнал перестанет расти, и обучение умрёт тихо.
Поэтому Срез Д не косметический.

## 5. Движение

Одна оркестрованная последовательность на экран: выводы появляются сверху вниз со сдвигом 40 мс,
`--ease`, длительность 120 мс — те же значения, что уже в `styles.css`. Больше не анимируется
ничего. `prefers-reduced-motion` отключает сдвиг, но **не** отключает скелетоны: они несут
информацию, а не украшают.
