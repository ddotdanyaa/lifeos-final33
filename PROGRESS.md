раз, когда активируется новый SW; (2) `registration.update()` на каждом boot — проверка апдейта
сразу, не по ленивому расписанию браузера; (3) обнаружен и запущен уже существующий (но не
выполнявшийся последние несколько коммитов) `npm run stamp` — привязывает бейдж версии в шапке
и имя SW-кэша к git-sha коммита, что и является штатным механизмом инвалидации кэша по плану
среза 1. **Урок**: `npm run stamp` — обязательный шаг перед каждым коммитом (см. `## Как
запустить` выше), пропуск ломает единственный способ владельца понять, на какой версии он
находится. Verified: playwright-скрипт — первая загрузка триггерит ровно один reload (новый SW
берёт control), повторный reload не зацикливается; `finance-bank-import.spec.mjs` (4/4) и
`player-dump-usability.spec.mjs` (2/2) зелёные после фикса; все 24 аудита + `npm run verify`
проходят (кроме заведомо недоступного в этой песочнице `audit-owner-rescue-final.mjs` — падает

**КРИТИЧНЫЙ баг найден владельцем на реальном ноутбуке (не в песочнице!) при обновлении до
этой ветки**: приложение вообще не рендерилось — пустая страница, ни шапки, ни меню. Причина:
`.gitignore` содержал строку `vendor/` (без ведущего слэша) — этот паттерн матчит ЛЮБУЮ папку
`vendor` на любой глубине дерева, а не только корневую `vendor/whisper-cpp/` (для которой она
задумывалась). Из-за этого `ui/vendor/affine-fuzzy-match.js` и `ui/vendor/xyflow-edge-paths.js`
(два маленьких MIT-vendored файла, статически импортируемых по цепочке `shell.js → graph.js →
GraphCanvas.js`) никогда не попадали в git — существовали только на диске у автора исходной
сессии. Любой свежий `git clone`/`git pull` этой ветки получал 404 на этот импорт → вся
цепочка ES-модулей ломалась → `shell.js` не инициализировался → пустая страница. Баг
существовал с момента создания этих файлов (см. DECISIONS.md, xyflow-донор и affine-fuzzy
донор), не был замечен раньше, потому что тестировался только в той же песочнице, где файлы
уже лежали на диске незакоммиченными.
Исправлено: `.gitignore` `vendor/` → `/vendor/` (только корень, `vendor/whisper-cpp/`
по-прежнему игнорируется), оба файла добавлены в git (`ui/vendor/` и `public-demo/ui/vendor/`).
**Verified по-настоящему** (не только в этой песочнице): `git clone --single-branch` в чистую
папку → `node server.mjs` на отдельном порту → playwright-проверка с нуля (пустой IndexedDB) —
приложение рендерится (после ~3-5с первого посева фикстур на пустой БД, это ожидаемо, не баг),
Дом/Деньги/Аудио/Граф — все без единой page-error, bank-import-форма и nav видны. Это первый
раз в сессии, когда фикс проверялся через настоящий fresh-clone, а не через уже тёплую
песочницу — стоит взять за привычку для доверия к "работает у меня" на будущее.

**Найден и закрыт настоящий кодек-баг плеера (эта же сессия, теперь с реальным доступом к
машине владельца)**: голосовая запись `Новая запись 29.m4a` кидала честную ошибку декодирования
в браузере. `ffmpeg -i` на реальном файле показал точную причину: `Stream #0:0: Audio: alac
(alac / 0x63616c61), 48000 Hz, mono` — **ALAC (Apple Lossless)**, кодек, для которого НИ ОДИН
браузер не реализует `decodeAudioData` (это не баг конкретного файла и не редкий контейнер —
целый кодек вне спеки Web Audio API). Файл не был битым (что владелец уже подтвердил через
Яндекс.Музыку) — decode честно падал ровно там, где и должен был.
Решение (без новых npm-зависимостей, §3.1 — реюз того, что уже стоит на машине): `server.mjs`
получил dev-only endpoint `POST /local-audio-transcode`, который принимает байты, ремуксит через
уже установленный локально `ffmpeg` (`C:\ffmpeg\bin`, есть в PATH) в PCM WAV во временный файл
и возвращает bytes; `decodeAudioTo16kMono` (`app.js`) при провале `decodeAudioData` пробует этот
endpoint как fallback ПЕРЕД честным отказом. На статическом `public-demo` (GitHub Pages, без
Node-сервера) запрос на `/local-audio-transcode` просто 404-ится, и код проваливается в тот же
честный текст ошибки, что и раньше — zero regression для той сборки (§7 — честность провайдеров,
никогда не имитировать успех).
**Verified**: синтетическая ALAC-фикстура `output/playwright/fixtures/alac-sample.m4a`
(`ffmpeg -f lavfi sine -c:a alac`, не личная запись владельца — приватность фикстур) +
новый `output/playwright/audio-alac-decode.spec.mjs` вызывает `decodeAudioTo16kMono` напрямую
через `window.__lifeosKnowledgeBase` (добавлен в список тестовых хуков) — зелёный. Полный набор
e2e (`human-public` + `final-human-product`, 11/11; `player-dump-usability` + `finance-bank-import`,
6/6) прогнан против свежего процесса `server.mjs` — все зелёные, регрессий нет. `npm run verify`
ok; все аудиты, кроме уже задокументированного `audit-owner-rescue-final.mjs` (не отдельная
регрессия — падает на несовпадении имени ветки и на отсутствии `gh CLI`, как и раньше, плюс
сейчас ожидаемо грязное дерево до коммита).
**Важное ограничение окружения**: порт 4173 в этой сессии держит node-процесс с повышенными
правами (PID из другого запуска) — убить его из песочницы нельзя (`Access is denied` даже от
того же пользователя, того же логон-сессии — похоже на UAC-повышение). Весь e2e-прогон в этой
записи шёл против отдельного тестового процесса на порту 4199 с тем же кодом. **Владельцу**:
после `git pull` нужно вручную перезапустить `npm start` (обычным Ctrl+C и `npm start` в своём
терминале), иначе порт 4173 продолжит отдавать старый `server.mjs` без нового эндпоинта, хотя
статические файлы (app.js/index.html и т.д.) обновятся сами, как обычно.

## Как запустить

```
npm start          # http://localhost:4173
npm run verify     # node --check + smoke (86 маркеров)
npm run stamp      # прошить git-hash в шапку UI + имя SW-кэша (перед каждым коммитом)
```

**Проверка «на что я смотрю»**: в правом верхнем углу шапки приложения виден хеш сборки
(`data-testid="build-version"`). Если он НЕ равен последнему коммиту (`git log --oneline -1`)
— ты смотришь на закэшированную старую версию: обнови страницу (Ctrl+Shift+R); новая
сборка сама инвалидирует старый service-worker-кэш при активации.

### ✅ Срок цели — из слов владельца (2026-07-26)
«Хочу купить машину до августа» оставалась целью **вообще без срока**: разбор дат работает по
конкретным дням, а месяц называют в записи чаще, чем число. Без срока не считается ни прогноз,
ни вероятность — цель существовала как надпись.

`parseGoalDeadline` читает месячный срок и различает предлоги по смыслу: **«до августа» — успеть
ДО начала месяца, значит 1-е число; «в сентябре» / «к декабрю» — внутри месяца, значит его
последний день.** Середину месяца не придумываем. Названный месяц всегда ближайший будущий:
«до марта», сказанное в июле, означает март следующего года.

Конкретный день сильнее месяца: если число названо, месячное правило не вмешивается.
У выведенного срока видно происхождение (закон №5): в карточке цели рядом с датой стоит «срок
распознан из слов «до августа»: успеть до начала месяца», а не общий провенанс объекта. У срока,
введённого руками, объяснения нет — и это честно видно.

**Проверить за 60 секунд**: наговори «Хочу купить машину до августа» → примени → открой цель:

### ✅ Позиция человека — это условие, а не потерянная запись (2026-07-26)
Строка прямо из целевого сценария владельца: **«Марина согласна на август если без кредита»**
уходила в «не разобрано». Имя система видела, месяц видела — а смысла записи не видела вовсе.
При этом именно условие решает, выполнима цель или нет.

Позиция распознаётся по форме: предикат отношения («согласна», «против», «не хочет», «готов»,
«просит», «требует», «настаивает», «возражает», «отказал», «разрешил») плюс имя человека
**строго перед ним**. Условие берётся из «если / при условии / только». Запись становится
утверждением (`claim` — коллекция уже была), у которого хранится кто сказал, какова позиция и
при каком условии она держится.

**Условие стоит НА ЦЕЛИ**, а не отдельной записью в стороне: на карточке цели появляется связь
типа «ограничивает» с дословным условием и подписью, кто его назвал. Иначе условие не участвует
в решении и никто не увидит его в нужный момент. Связь ищется по общей ОСНОВЕ предметных слов
(«машину» в условии ↔ «машина» в цели): русский склоняет.

Позиция видна и в карточке самого человека — это то, что владелец о нём знает.

Попутный дефект, найденный спекой: «Против кредита на машину» давало **человека по имени
Против** — заглавное слово позиции попадало в имена. Имя теперь должно стоять строго перед
позицией, а сами слова позиции добавлены в стоп-лист имён.

**Проверить за 60 секунд**: наговори «Хочу купить машину до августа», потом «Марина согласна на
август если без кредита» → примени → открой цель → вкладка «Связи»: «ограничивает · Марина —
согласна. Условие: без кредита».
Verified: `person-stance.spec.mjs` 5/5.

### ✅ Срезы: один артефакт — много представлений (2026-07-27)
Канон обещает «данные ≠ представление», но в продукте это оставалось словами: сохранённые
поиски существовали в хранилище **без единого элемента интерфейса** (`grep savedSearches ui/`
не находил ничего). Теперь в Базе есть **срез** — представление над теми же артефактами:
источник (Задачи · Цели · Привычки · Деньги · Наблюдения · Утверждения · Захваты), одно условие
(поле · операция · значение) и вид (список или таблица). Копии данных не создаётся: строка среза
ведёт в тот же объект, что и любой другой экран.

**Языка запросов нет намеренно.** У донора (Dataview) есть DataviewJS — произвольный JS в
заметке; это дыра и в приватность, и в предсказуемость. Здесь всё выбирается из закрытых
списков: сломать срез опечаткой невозможно, а прочитать его может человек, а не парсер.
Сохранённый срез получает человеческое имя («Деньги — вид равно доход»), чек в Контроле и
возврат по клику. Повторное сохранение того же среза (закон №4) обновляет, а не удваивает.

**Проба вскрыла ложь, которую все 10 тестов пропустили.** С выбранным «вид равно» и ещё пустым
значением браузер показывал выбранным первый пункт списка — «доход», подпись писала
«условию отвечают 2», а в таблице стояли и доходы, и расходы: экран обещал одно, показывал
другое. Причина в том, что пустое значение = «условие не задано», а `<select>` без пустого
пункта всегда показывает первый. Теперь условие считается заданным только когда оно **полное**
(поле + операция + значение), в списке значений первым идёт «любое», подпись говорит
«условие ещё не дописано — пока показаны все», а сохранить такое можно только как «— все».

**Проверить за 60 секунд**: База → панель «Срезы» → «Откуда: Деньги» → «Поле: вид» →
«Значение: доход» → «Таблица» → «Сохранить срез».

ошибка дважды, и в UTC+3 они гасили друг друга — верный ответ по неверному пути.

версия». Всё напечатанное исчезало вместе со страницей. У владельца воркер стоит давно — изо дня в
день не видно; видно при ПЕРВОМ знакомстве с продуктом и в каждом прогоне e2e на чистом профиле.
Именно поэтому спеки разбора падали не на разборе, а на пропавшем вводе. Теперь перезагружаемся
только при СМЕНЕ контроллера — исходный смысл фикса 2026-07-22 (владелец видит старую версию)
сохранён полностью.
