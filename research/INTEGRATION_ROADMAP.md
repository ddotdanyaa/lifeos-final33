# INTEGRATION ROADMAP — что берём из доноров и в каком порядке

Итог анализа 11 донорских проектов (детали функций — `docs/DONOR_FUNCTION_CATALOG.md`, 160+;
лицензии/стек — `docs/OSS_DONOR_AUDIT.md`; модели/алгоритмы — `MASTER_ARCHITECTURE_INDEX.md` /
`MASTER_ALGORITHM_INDEX.md`). Здесь — только то, что решает: **что берём, что не берём, и когда**.

**Железное правило:** LifeOS остаётся ЕДИНОЙ артефактной системой. Никаких новых сущностей,
никаких отдельных графов/памятей. Одна модель — много представлений. Всё новое — проекция или
слой поверх существующих 47 коллекций и конвейера proposal→preview→apply→receipt.

**Стек-реальность (проверено по raw LICENSE и составу файлов):** все 11 доноров — серверные
(Python/Java/ClojureScript/React). Ни один **не встраивается кодом** в наш локальный vanilla-браузер.
Берём алгоритмы, модели данных, UX и инженерные компромиссы — реализуем сами.

## Сводка по донорам (8 вопросов, сжато)

### Graphiti (Apache-2.0, Python+Neo4j) — ГЛАВНЫЙ донор для графа-разума
1. **Даёт:** темпоральный граф знаний: факты с окном валидности, инвалидация вместо удаления, эпизоды-провенанс, гибридный поиск (семантика+ключи+обход), реранк по расстоянию в графе, community detection.
2. **Берём:** bi-temporal рёбра (`since`/`until`), supersede вместо delete, трассировка факта до источника, объяснение связи, реранк соседей по близости.
3. **Не берём:** Neo4j-зависимость, LLM-экстракцию триплетов в облаке, их схему узлов.
4. **Дублирует у нас:** provenance (source→note→receipt) — уже есть; типизированные коллекции — уже есть (47); инкрементальный пересчёт — `rebuildIndexes`.
5. **Почти без изменений:** формула «противоречие → инвалидировать старое ребро, сохранив историю».
6. **Переписать под артефакты:** темпоральность как поля рёбер нашей проекции `computeGraphProjection`, НЕ отдельная БД. (`since` уже внедрён.)
7. **Лучший паттерн:** у каждой связи — тип, сила, объяснение, время появления. Это ровно закон №8 канона.
8. **Критично для тестирования:** без инвалидации и провенанса вечерний дамп 20–30 голосовых превращает граф в кашу противоречий.

### Neo4j GDS (GPL, Java) — эталон графовых алгоритмов (только идеи, GPL)
1. **Даёт:** 65+ алгоритмов: центральности, сообщества, пути, link prediction.
2. **Берём (как формулы):** degree (хабы — уже есть), PageRank/Personalized PR («что влияет сильнее»), betweenness («мосты»), Louvain/label-propagation (кластеры тем), shortest path («как связаны A и B»), Adamic-Adar (предсказание связей).
3. **Не берём:** саму СУБД, Cypher, серверный рантайм, embeddings-модули (Node2Vec/FastRP — тяжело).
4. **Дублирует:** degree-centrality уже реализована (`detectGraphHubs`).
5. **Почти без изменений:** алгоритмы общеизвестны — реализуем сами на нашем графе.
6. **Переписать:** все алгоритмы работают на проекции артефактов, лениво и инкрементально.
7. **Лучший паттерн:** «влияние» считается, а не декларируется.
8. **Критично:** PageRank + shortest path нужны для ответов графа «что блокирует цель».

### Mem0 (Apache-2.0) + Cognee (Apache-2.0) — память
1. **Даёт:** многоуровневая память, скоринг важности, decay, разрешение конфликтов, ingest→cognify→search.
2. **Берём:** importance = свежесть+частота+связность; decay как вес (не удаление); ADD-only + supersede; дедуп фактов.
3. **Не берём:** отдельное хранилище памяти, векторную БД, серверные пайплайны.
4. **Дублирует:** ADD-only и чеки — это уже наш §7; дедуп частично есть (merge-review).
5. **Почти без изменений:** формула скоринга важности.
6. **Переписать:** память = слой ранжирования НАД артефактами, не новая коллекция.
7. **Лучший паттерн:** у каждого факта есть источник и история изменений.
8. **Критично:** без скоринга после 20–30 записей важное тонет.

### LlamaIndex (MIT) + Haystack (Apache-2.0) — RAG/поиск
1. **Даёт:** chunking, ретриверы, гибридный поиск, реранкинг, синтез ответа, инспектируемый конвейер компонентов.
2. **Берём:** retrieve→rerank→synthesize с цитатами; chunk-уровневые цитаты; fusion лексики+вектора+графа; роутинг запроса.
3. **Не берём:** Python-рантайм, векторные БД, LLM-цепочки в облаке.
4. **Дублирует:** minisearch (лексика) есть; цитаты в чате есть (C1.4); `buildOllamaChatPrompt` есть.
5. **Почти без изменений:** порядок стадий конвейера и идея «каждая стадия видима».
6. **Переписать:** конвейер на наших индексах, локально, с честным отказом при отсутствии контекста.
7. **Лучший паттерн (Haystack):** пайплайн инспектируемый — видно, что нашлось и почему.
8. **Критично:** «Спросить LifeOS» с цитатами на свои артефакты — иначе продукт не отличим от чата.

### LangGraph (MIT) — агенты
1. **Даёт:** граф состояний, checkpointer, conditional routing, human-in-the-loop interrupt, time-travel.
2. **Берём:** шаги как узлы над типизированным состоянием; пауза → подтверждение → продолжение; история прогонов.
3. **Не берём:** Python-рантайм, их API.
4. **Дублирует:** checkpoint = наш `commit` в IndexedDB; HITL = наш preview→approve→receipt; Agent Center (срез 13) — основа.
5. **Почти без изменений:** модель «план → подтверждение → исполнение → отчёт → квитанция» (= канон Agents.dc.html).
6. **Переписать:** состояние сценария — артефакт, шаги — предложения.
7. **Лучший паттерн:** необратимый шаг всегда помечен и требует подтверждения.
8. **Критично для теста:** Hermes/Telegram-путь — это агент-исполнитель.

### Logseq (AGPL — ТОЛЬКО идеи) — знания
1. **Даёт:** outliner-блоки, block-refs, journal, page-properties, запросы-как-представления.
2. **Берём (идеи):** адресуемые блоки/секции, транклюзия, свойства артефакта, живые срезы.
3. **Не берём:** НИ СТРОКИ КОДА (AGPL) + ClojureScript вне стека.
4. **Дублирует:** вики-ссылки, беклинки, daily-поток, глобальный/локальный граф — всё уже есть.
5. **Почти без изменений:** ничего (лицензия).
6. **Переписать:** свойства и запросы поверх артефактов.
7. **Лучший паттерн:** unlinked references → кандидаты связей (ядро наших инсайтов-связей).
8. **Критично:** нет (наш фундамент это уже покрывает).

### AnythingLLM (MIT, React) + Open WebUI (кастомная лицензия) — UX локального AI
1. **Даёт:** воркспейсы, документ→эмбеддинги, цитаты, селектор моделей, RAG-UI.
2. **Берём:** UX-паттерны воркспейсов и честных статусов провайдеров.
3. **Не берём:** React/Svelte-код, Open WebUI — вообще только смотреть (branding-clause).
4. **Дублирует:** наши воркспейс-линзы, честные статусы провайдеров (§7), Ollama-интеграция.
5. **Почти без изменений:** ничего (стек/лицензия).
6. **Переписать:** —
7. **Лучший паттерн:** модель и её статус всегда видны пользователю.
8. **Критично:** нет.

### Graphify (MIT, Python) — визуализация графа (по просьбе владельца — как источник идей)
1. **Даёт:** интерактивный HTML-граф, кластеризация (Leiden/сообщества), god-nodes, объяснимые связи, экспорт в Obsidian, отчёт GRAPH_REPORT.
2. **Берём:** кластеризация с ИМЕНАМИ сообществ, ранжирование хабов, «объясни узел» текстом, кратчайший путь между двумя узлами как ответ.
3. **Не берём:** Python-пайплайн как рантайм продукта (уже используется как ИНСТРУМЕНТ АГЕНТА — `.agents/skills/graphify/`, это не фича продукта).
4. **Дублирует:** наш canvas-граф, зум/минимапа/фокус (G1 GRAPH_ALIVE), degree-хабы.
5. **Почти без изменений:** идея «граф отдаёт текстовый отчёт», а не только картинку.
6. **Переписать:** именованные кластеры тем поверх нашей проекции.
7. **Лучший паттерн:** граф не hairball — сообщества свёрнуты, раскрываются по фокусу.
8. **Критично:** без кластеризации граф после 20–30 записей станет клубком.

**Что осталось (честно):**
- Наблюдение со сроком («Сегодня опять ничего не сделал») правилами не ловится: дата уводит
  запись в обычный разбор. Сделано намеренно — при сомнении не решаем за владельца (закон №6);
  полное решение — фоновый LLM-разбор (P2-5).
- **P2-1 семантические соседи**: сделана ЛЕКСИЧЕСКАЯ половина — «Похожее по тексту» (tf-idf по
  трёхбуквенным кускам с косинусом, кэш по графу жизни, служебная шапка тела вырезается). Это
  сходство ТЕКСТА, и так оно и подписано в интерфейсе. Настоящие эмбеддинги не сделаны: нужна
  модель и решение владельца о её загрузке.
